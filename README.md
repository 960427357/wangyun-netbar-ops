## 为什么不能直接问 AI

普通 AI 对着这个后台会犯四类错，每一类都真踩过：

- **「补货」不等于「上架」。** 补货弹窗的「数量」是入库数，会虚增总库存。只想把仓库的货搬到吧台，
  必须用商品表格的内联框改 `默认吧台库存 +N` / `未出货 −N`。踩过这个坑，账面多记了 20 瓶。
- **计费设置整块只读。** 页头有「当前版本无法修改」提示，反复点保存只会误判成操作失败。
- **价格是三层叠出来的。** `区域基准价 × 费率明细 × 等级折扣`，等级面板显示红字时折扣不生效。
- **接口不能自己 fetch。** 裸请求返回 406，只能用 `page.waitForResponse` 截页面自己发的包。

这些都在文档里写明了判断依据，不是凭印象。**没验证的项单独标出来，不硬写成结论。**

```bash
git clone https://github.com/960427357/wangyun-netbar-ops.git \
  ~/.workbuddy/skills/wangyun-netbar-ops
```

## 依赖

脚本依赖 `playwright-cli` 与一个**已登录的有头浏览器会话**：

```bash
npm install -g @playwright/cli@latest
npx playwright install chromium        # 首次需要，否则 open 会找不到浏览器

export PATH="$PATH:$APPDATA/npm"
playwright-cli open https://wyb.5188cloud.net/login --browser=msedge --headed --persistent
```

有 Node ≥ 20 就能跑。装完可自检：

```bash
node scripts/detect-browser.mjs
```

> **浏览器后端只用 playwright。** ego-browser 评估过——能跑且长流程更快，但 API 与 Playwright
> 不兼容（不认 `locator` / `getByRole`），要额外维护一套写法，**已决定暂不采用**。
> 评估结论存档在 `references/90-浏览器工具适配.md`。

压图脚本 `scripts/fit-image.py` 用 Python + Pillow（**唯一一个非 Node 脚本**，只处理本地文件、不碰浏览器）：

```bash
pip install pillow
python scripts/fit-image.py 图.png --check     # 先体检
```

平台所有图位硬上限 **500KB**，超限是静默失败，上传前一律先过这个脚本（铁律 #20）。

登录必须由使用者本人完成。本包不包含、不索取、不记录任何账号密码。

## 会用到的几条路

**查价**：机位 → 区域（终端管理）→ 基准价（区域方案）→ 折扣（会员等级）→ 通宵（包时段策略 / 上网卡专场卡）。

**上架到吧台**：商品管理搜商品名 → 内联框 `默认吧台库存 +N`、`未出货 −N` → 失焦即存 → 刷新复核总库存不变。

**新增商品**：商超管理 → 基础管理 → 商品名称 → 添加 → 填名称（可选图片）→ 确认。

**配员工提成**：员工激励 → 当前规则 → 新增。先选「适用场景」，**提成方式选项会跟着变**
（会员拉新只有固定提成）。「销售额提成」是分段累进、「销售总额提成」是够档整笔乘，**别选错，差一倍**。
配完一定要算成本，或跑 `audit-commission.js` 审计。

> ⚠️ **配规则之前先过两关，否则一分钱都发不出去**：
> ① 基础设置 → 网吧配置 → 基础配置，两个「派送人」开关（收银端 / 客户端）都打开——它就是「选择销售人」的总闸；
> ② 开单时有人在岗：排了班的人，或**当月零排班**走自由打卡、已打上班卡的人。
> **不排班 → 收银台和客户端都选不到这个人。** 详见 `references/13-员工激励.md`「前置两关」、
> `references/15-排班与班次.md` §四。

**发会员通知**：服务管理 → 会员通知宣传 → 通知记录 → 新增 → 标题+内容+通知时间 →
`保存并提交审核`（行内「提交审核」会报权限不足）。时间要 `YYYY-MM-DD HH:mm`，
且必须去掉 input 的 readonly 才能打字进去。**状态停在「待审核」不会自己发**，要盯到「已发送」。

**做团购券**：先「团购套餐 → 新增」建券（现金网费 + 赠送网费 = 券面额），
再到「上架管理」上架，门市价填券面额、团购价填实付、**库存一律 9999**，
确认框点「提交」（不是「确定」）。

**补部门**：员工管理 → 部门管理 → 新增 → 只填「部门」即可（主管可空）→ 保存 → 刷新复核人数列。
部门一建，员工新增的「部门」下拉就能选到。

**关掉某台机子的占座/订座**：服务管理 → 机位图 → APP机位图 → 对应穿梭框（右框=参与，左框=不参与）
→ 勾选机位 → 点左箭头 → 点该区块的保存。全站只有这一处能按单台机位放行。

## 版本与打包

版本号写在 `SKILL.md` 的 `version:` 字段，每次改动都在 `CHANGELOG.md` 留一条。

打包用 `scripts/build-release.sh`（`git archive` 而非 `zip -r`，**只打已提交内容**，同 tag 重打结果一致）：

```bash
bash scripts/build-release.sh            # 打当前 HEAD，版本号从 SKILL.md 读
bash scripts/build-release.sh v1.6.30    # 打指定 tag
bash scripts/build-release.sh --all      # 全部 v1.6.25 起的 tag 各打一个
```

发版流程：

1. 改 `SKILL.md` 的 `version:` 字段与 CHANGELOG
2. `git commit` → `git tag -a vX.Y.Z` → `git push origin main --tags`
3. `bash scripts/build-release.sh vX.Y.Z`
4. `gh release create vX.Y.Z dist/wangyun-netbar-ops-vX.Y.Z.zip --title "…" --notes-file …`

Release 说明的写法约定：**第一段是「一句话结论」**，说明这次到底发现了什么坑；
未验证的项单独列一节，不硬写成结论。
