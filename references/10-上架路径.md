## 三、商品上架三条路径（按效率排序）

### 路径 A：单品新增（最稳，推荐脚本化）
销售管理 → 商超管理 → 基础管理 → 商品名称 → 添加
- 路由 `/marketManage/goodsManage/baseManage/goodsName`
- 弹窗「添加商品」字段
  - 商品名称（必填，placeholder `请输入商品名称`）
  - 商品图片（可选，jpg / png / jpeg，**≤500KB，超限静默失败**；传前先跑 `python scripts/fit-image.py <图> --square --width 800`，见铁律 #20）
- 按钮：取消 / 继续添加（连录保持弹窗）/ 确认

### 路径 B：批量导入（一次 ≤100 种）
销售管理 → 商超管理 → 商品管理 → 导入 → 旺云数据
- 路由 `/marketManage/goodsManage/shop/goods`
- 弹窗「导入文件（旺云数据）」：浏览 → 选择文件 → 上传数据
- 限制：单次不超过 100 种商品，上传后不可离开本页
- 注意：界面未提供模板下载，需导出既有商品反推列格式，或向平台客服索取模板

### 路径 C：表格内联编辑（存量商品维护）
商品管理表格可直接改 进货价 / 销售价 / 兑换所需积分，用 +/- 调库存，行内操作 补货 / 编辑 / 删除 / 下架 / 报损

## 四之二、积分兑换 ≠ 换购（两个独立机制，最容易混）

商品编辑弹窗里有两个看起来都像"促销"的字段，**它们不是一回事，互不依赖**：

| | **积分兑换** | **换购** |
|---|---|---|
| 字段 | 兑换所需积分 | 开启换购（开关）+ 换购金额（元） |
| 接口 | `integral` | `exchange`(0/1) + `exchangePrice` |
| 顾客付什么 | **只用积分**（填 100 就是 100 积分换走） | **凭证 + 加价**：中奖小票 5 元换购、瓶盖 1 元换购 |
| 场景 | 签到积分出口、会员福利 | 厂家促销核销（小票/瓶盖/拉环） |

- **只填「兑换所需积分」就能生效**，不需要打开「开启换购」（2026-10-31 实测：填 100 → 保存 → 接口 `integral=100`、`exchange` 仍为 0）。
- 两者可以同时存在：本店红牛就是 `exchange=1 / exchangePrice=1`（1 元换购）+ `integral=20`。
- ⚠️ 打开「开启换购」后，右侧才会出现「换购金额」输入框；**换购金额填 0 等于 0 元送**，别只开开关不填价。

### 商品编辑弹窗全字段（13 项，顺序即 tab 顺序）

商品分类 / 商品属性（普通商品，只读）/ 商品名称 / 商品单位 / 商品条形码 /
商品标签 / 允许网民自助购买（**是·否 单选**，radio 值 1/0）/ **兑换所需积分** /
进货价 / 销售价 / 销售时间 / **开启换购**（switch）/ 允许会员网费购买（switch）

> 🔴 **「商品入库」弹窗比「编辑商品」弹窗多三项**：数量 / 总未出货库存 / **上架吧台**。
> **上架动作就在「上架吧台」里填出货数量**，编辑弹窗没有这个字段——已经建好但没出货的商品，
> 只能走「补货」或重新入库把货铺到吧台。字段与判断方法见 `07-商品销售.md` §2.2.3。
> 另：「商品标签」是**可多选**的规格选项组，一个商品能挂多个组、每组顾客单选一个选项，详见 §2.2.2。

> 「商品名称」等字段的值**不在 `input.value` 里**（value 恒为空，名称以文本形式渲染在
> `.el-form-item` 内）。想校验"弹窗里是不是我要改的那个商品"，必须读 `form-item` 或
> `dialog` 的 `innerText`，读 input.value 永远失败。

### 推荐路径：直接改表格里的「兑换所需积分」列

商品管理表格该列是**行内 input**，改完失焦即提交，比走弹窗快且不会串号。
批量设置积分时优先用这条路径；只有需要连改多个字段才进弹窗。

## 四之三、商品表格的 DOM 结构（批量脚本必须先看懂这个）

`.el-table__body tbody tr` 里混着两级行：

```
外层：分类展开行 <tr><td colspan="12" class="el-table__expanded-cell">
        └─ 内嵌自定义表 <table class="draggable-table">
             └─ 商品行 <tr class="goods_tr">   ← 一行一个商品
```

**致命陷阱**：用 `.el-table__body tbody tr` 找"含某商品名的行"，命中的是**整个分类的展开行**
（里面套着该分类全部 6 个商品）。此时 `tr.querySelector('button')` 取到的是**该分类第一个商品**
的「编辑」，于是点「乐虎」会弹出「红牛」——而且保存成功，值就悄悄写到了别的商品上。

正确选择器：**`tr.goods_tr`**（本店 38 个商品 = 38 行），商品名在 `td[2]`，
操作按钮在同一 `goods_tr` 内。列下标：`3`=进货价、`4`=销售价、`5`=单位、**`6`=兑换所需积分**、
`7`=默认吧台库存、`8`=总库存、`10`=操作。

### 弹窗异步的两个时间陷阱

1. **打开要等**：点「编辑」后弹窗内容是异步填充的，固定 sleep 会读到上一个商品。
   判据：可见 `.el-dialog` 数量 === 1 **且** 其 `innerText` 含目标商品名。
2. **关闭也要等**：点「保存」后弹窗有消失动画，动画期间 `offsetParent` 仍非 null。
   不等到"可见弹窗数归零"就开下一个，会对着旧弹窗再点一次保存 → **值写到上一个商品上**。

> 2026-10-31 踩坑实录：只等固定 1.8s 批量跑 16 个商品，结果只有 3 个真的落库且值全部错位
> （茶里王变 125、红牛从 20 变 75、牛肉面变 75），13 个没落上。改成
> 「等=1 且名称匹配 → 写 → 存 → 等=0 → 下一个」后 15/15 一次通过。

## 五、自动化运行方式

已登录的 playwright-cli 有头会话中执行：

```bash
# 1. 确认会话在线
playwright-cli list

# 2. 运行批量新增脚本（把商品清单写进 scripts/add-goods.js 的 products 数组）
playwright-cli run-code --filename scripts/add-goods.js
```

脚本骨架见 `scripts/add-goods.js`。核心逻辑为循环：点「添加」→ 填名称 → 可选传图 → 非末条点「继续添加」、末条点「确认」。

## 六、风险提示

- 图片上传走 `input[type=file]`，若弹窗用自定义上传组件需改用 `setInputFiles` 定位。
- 批量导入的列格式未公开，导入前务必先用 1 到 2 条做试运行。
- 站点为生产后台，脚本应加逐条结果校验，避免静默失败。
