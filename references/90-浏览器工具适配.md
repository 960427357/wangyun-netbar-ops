# 90. 浏览器工具适配（Playwright CLI / ego-browser）

本技能包的所有操作都要经过浏览器。浏览器有两种驱动方式，本文说明它们的边界、选型规则和写法对照，
保证**同一套技能在两种环境下都能跑**。

---

## 结论先行

1. **「在 ego 里装 playwright-cli」不成立**，不是配置问题，是架构问题（见 §90.1）。
2. 正确形态是**并存**：`playwright-cli` 是基线，`ego-browser` 是加速器。
3. 发给别人时，**playwright 保证能用**（装了 node 就行）；ego 是可选提速，缺了不影响功能。

---

## 90.1 为什么不能在 ego 内跑 Playwright

三条实测证据，任一条都足以否掉这条路：

### 证据 1：ego 官方规范明文禁止

`ego-browser skill` 输出的规范里写着：

> Do not import Playwright or launch another browser.

这是 ego 对脚本的硬约束。它的 Node 运行时（内嵌 v24.22.1）只允许通过它自己的 TaskSpace / Page API 操作浏览器。

### 证据 2：ego 不开放任何调试端口

实测（11 个 `ego.exe` 进程）：

```powershell
$egoPids = (Get-Process ego).Id
Get-NetTCPConnection -State Listen | Where-Object { $egoPids -contains $_.OwningProcess }
# 结果：无任何监听端口
```

而 `playwright-cli attach --cdp` 和 `chromium.connectOverCDP()` 都**必须**先有一个 CDP 端点。
ego 不提供端点，外部 Playwright 无从接管。

### 证据 3：ego CLI 没有启动/挂载动词

```
ego-browser --help
  ego-browser import ...    # 导入浏览器 profile
  ego-browser skill         # 打印使用手册
  ego-browser upgrade       # 升级
  ego-browser nodejs ...    # 跑内嵌 node 脚本
```

没有 `launch`、没有 `attach`、没有 `--remote-debugging-port`。

> 补充：ego 内部确实有 `page.cdp()` / `task.cdp()`，但那是**脚本内部**的底层逃逸口
> （用于 `Fetch.enable`、`Page.stopLoading` 这类诊断），不对外暴露端点，
> 无法让外部 Playwright 接进来。

## 90.2 两者的真实差异

| 维度 | playwright-cli | ego-browser |
|---|---|---|
| 驱动方式 | 一条命令一步（逐步驱动） | 一次提交整段 JS（注入式） |
| 浏览器 | 自带 Chromium / 可指定 Edge | 自带 Chromium 156 |
| 运行时 | 系统 node | 内嵌 node v24.22.1 |
| 会话寿命 | 随进程，需后台常驻 | TaskSpace 常驻，跨命令存活 |
| 单步开销 | 高（进程启动 + 协议往返） | 低（同一上下文内执行） |
| 长流程 | 慢，随步数线性放大 | 快，一次往返跑完 |
| API | 完整 Playwright API | 自定义小 API，**不是** Playwright |
| 等待 | auto-wait，自动等元素可交互 | 必须显式 `waitForSelector` / `waitForFunction` |
| 失败恢复 | 稳，返工少 | 踩空要整段重跑 |
| 调试 | 强，可看请求 / 响应体 | 弱，主要靠 `console.log` |
| 可移植 | 有 node 即可 | 需安装 ego lite |

**速度差距随流程长度放大**：20 步的流程，playwright 要 20 次往返，ego 只要 1 次。

## 90.3 选择规则

| 你在做什么 | 用哪个 | 原因 |
|---|---|---|
| 第一次摸一个不熟的后台页面 | playwright | 能看网络请求，不用先写脚本 |
| 抓接口、找参数 | playwright | `page.on('response')` 直接看响应体 |
| 反复跑的长流程（上架、批量配置） | ego | 一次往返跑完，快数倍 |
| 定时 / 无人值守任务 | ego | TaskSpace 常驻，不依赖 shell 进程存活 |
| 发给别人、不确定对方环境 | playwright | 零额外安装 |
| 需要 canvas / 拖拽 / 坐标操作 | 两者皆可 | ego 有 `mouse.*`，playwright 更细 |

**默认策略：先用 playwright 把流程跑通并抓清接口，再决定是否固化成 ego 脚本。**

## 90.4 写法对照

### 90.4.1 执行单位

**playwright-cli** — 每步一条命令，浏览器需后台常驻：

```bash
playwright-cli open --browser=msedge --headed --persistent; sleep 3600  # 后台任务挂住
playwright-cli run-code --filename scripts/read-goods-sale.js           # 复用同一会话
```

**ego-browser** — 整段脚本一次提交（中文必须写在文件里，不能塞进 `-e`）：

```bash
ego-browser nodejs < scripts/ego/read-goods-sale.mjs
# 或
ego-browser nodejs -e "await import('file:///C:/path/to/task.mjs')"
```

### 90.4.2 定位元素（最大差异）

```js
// playwright
await page.locator('.el-table__row').nth(2).click();
await page.getByRole('button', { name: '保存' }).click();
await page.locator('tr', { hasText: '红牛' }).first().click();
```

```js
// ego —— 用选择器字符串，或 loc= 语义定位
await page.click('css=.el-table__row >> nth=2');
await page.click("loc=role:button[name='保存']");
await page.click('css=tr:has-text("红牛") >> nth=0');

// 或先 snapshot 拿 ref，再点
console.log(await page.snapshot());   // 输出里带 @21 这类 ref
await page.click('@21');
```

**ego 支持的 Playwright 子集**（其余一律报错）：

- `css=...`
- 末尾 `:has-text("...")`、`:text-is("...")`
- `>> nth=N`（N 可为 `-1` 或非负整数）
- `loc=role:...[name*="..."]`（可访问名子串）

**ego 不支持**：`locator()`、`getByRole()`、`expect()`、`route()`、`context()`。
现有脚本里 `locator` 出现 55 次、`getByRole` 11 次——迁到 ego 时必须逐个改写。

### 90.4.3 等待

```js
// playwright：click 自带 actionability，通常不用写等待
await page.locator('button:has-text("保存")').click();
```

```js
// ego：动作前显式等待，否则踩空
await page.waitForSelector('css=.el-table__row', { state: 'visible' });
await page.click("loc=role:button[name='保存']");
await page.waitForFunction(() => document.querySelectorAll('.el-table__row').length > 0);
```

**两边都应避免 `waitForTimeout` / `sleep`。** 本技能包现有 204 处固定等待合计约 384 秒，
是当前最大的性能负担——无论用哪个后端，这项优化都是第一优先。

### 90.4.4 读表格

```js
// playwright
const rows = await page.locator('.el-table__body tr').evaluateAll(els =>
  els.map(tr => Array.from(tr.querySelectorAll('td')).map(td => td.innerText.trim()))
);
```

```js
// ego —— evaluate 回调不能引用外部变量，参数只能通过第二个参数传（仅限可 JSON 序列化的单个值）
const rows = await page.evaluate(() =>
  Array.from(document.querySelectorAll('.el-table__body tr')).map(tr =>
    Array.from(tr.querySelectorAll('td')).map(td => td.innerText.trim())
  )
);
```

### 90.4.5 抓接口数据（优先路线）

DOM 抓表既慢又脆。**能走接口就走接口**——本技能包 15 个抓表脚本里目前只有 1 个这么做。

```js
// ego：page.fetch 在页面上下文发请求，自动带上当前登录态
const res = await page.fetch('/business-wy/goodsDiscount/list', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ page: 1, limit: 100 }),
});
const data = await res.json();
```

```js
// playwright：在页面里 fetch，同样带 cookie
const data = await page.evaluate(async () => {
  const r = await fetch('/business-wy/goodsDiscount/list', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ page: 1, limit: 100 }),
  });
  return r.json();
});
```

一次拿全量，省掉翻页和 DOM 解析，也顺带解决「切 100 条/页」这个一直没落地的要求。

### 90.4.6 登录态

```bash
# playwright：持久化 profile，登录一次后续复用
playwright-cli open --browser=msedge --headed --persistent
# 也可导出/导入
playwright-cli state-save auth.json
playwright-cli state-load auth.json
```

```js
// ego：TaskSpace 常驻，登录态一直在；需要用户手动登录时交接控制权
await task.handOff();          // 把浏览器交给用户，他去登录
await task.waitForControl();   // 收回控制权后继续
```

**永远不要索取、代填、记录账号密码。**

## 90.5 分发依赖说明

给别人用这套技能时，明确告知以下前提。

**最低要求（必装）**

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | ≥ 20 | 系统 node，`node -v` 可查 |
| playwright-cli | `npm i -g @playwright/cli` | 提供 `playwright-cli` 命令 |
| 浏览器内核 | `npx playwright install chromium` | 否则 `open` 会报找不到浏览器 |

装完自检：

```bash
node scripts/detect-browser.mjs
```

**可选加速（ego）**

| 项 | 说明 |
|---|---|
| ego lite | 从官网安装，自带 Chromium 156 + node v24 |
| 命令位置 | 不一定在 PATH，`detect-browser.mjs` 会自动扫安装目录 |

**探测脚本会告诉你该用哪个后端**

```bash
node scripts/detect-browser.mjs          # 人类可读
node scripts/detect-browser.mjs --json   # 机器可读
```

退出码 `0` 表示至少一个后端可用，`1` 表示两个都没有。

## 90.6 迁移检查清单

把现有 playwright 脚本迁到 ego 时逐项过一遍：

- [ ] `locator(...)` → 选择器字符串 / `loc=...` / snapshot ref
- [ ] `getByRole(...)` → `loc=role:...[name='...']`
- [ ] `evaluateAll(...)` → `evaluate(...)`（在回调内自己 `querySelectorAll`）
- [ ] `expect(...)` → `waitForSelector` / `waitForFunction`
- [ ] `route(...)` / `waitForResponse` → `page.cdp('Fetch.enable')`，或直接改走 `page.fetch`
- [ ] 回调里引用的外部变量 → 作为 `evaluate` 第二个参数传入
- [ ] 固定 `waitForTimeout` / `sleep` → 换成可观测条件
- [ ] 中文文本 → 写进 `.mjs` 文件，**不要放进 `-e` 参数**（shell 会破坏编码）
- [ ] 文件读写路径 → 用绝对路径（ego 脚本不继承 shell 的 cwd 和环境变量）

## 90.7 一句话记忆

**playwright 用来「搞明白」，ego 用来「跑得快」；发给别人的那版，必须能在只有 playwright 的机器上跑通。**
