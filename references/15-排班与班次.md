# 15 · 排班与班次

> 适用于：给某个岗位配两个班（早/夜）、按人排月班表、验证是否每个班都有人在岗。
> 2026-10-31 在「演示门店」实测落库（3 名虚拟收银员 · 2026 年 11 月整月）。

---

## 一、两个地方，两件事，别混

| 层 | 路径 | 做什么 | 改一次影响谁 |
|---|---|---|---|
| **班次定义** | 员工管理 → 岗位管理 `/staffManage/post` | 这个岗位分几个班、每班的起止时间 | 该岗位**所有**员工 |
| **月度排班** | 员工管理 → OA管理 → 排班 `/staffManage/oa/scheduling` | 某人某天上班次 | 只影响**个人**当天 |
| **打卡模式** | 不由人配，**由排班表自动判定**（见 §四） | 有排班 → 按排班打卡；整月零排班 → 自由打卡 | 只影响**本人**当下算不算「在岗」 |

顺序不可颠倒：**先有班次，才能排班**。排班弹窗里的下拉选项直接就是岗位的班次名
（本例只有「早班」「夜班」两项），岗位没配好的班次不会出现在下拉里。

## 二、班次定义（岗位管理）

### 2.1 列表

列：岗位名称 / 部门 / 班次 … / 操作。收银员一行会显示 `早班(09:00-21:00) 夜班(21:00-02:59)` 这类摘要。

### 2.2 编辑弹窗

每个班次一行：**班次名称 + 开始时间 + 结束时间**（时间控件，`HH:mm`）。
允许跨零点：`21:00 → 09:00` 是合法的，系统不做"结束须大于开始"的拦截。

实测案例：收银员原夜班写的是 `09:00 → 02:59`（既和早班重叠、又没覆盖到 03:00–09:00），
改成 `21:00 → 09:00` 后才是真正的两班倒。

> 🔴 **检查项**：早班结束时间必须等于夜班开始时间，夜班结束必须等于早班开始，
> 否则一天里必有时段无人（值班表看着满，实际漏班）。

### 2.3 保存

底部「保 存」→ 弹 toast，列表即时刷新。**没有二次确认**。

## 三、月度排班（OA管理 → 排班）

### 3.1 页面结构

- 顶部：`月份`（`input[placeholder="请选择 月份"]`，值形如 `2026-11`）、`岗位`下拉、按钮 **`搜 索`** / `清 空` / `清除当月所有排班`
- 表格：列 = `岗位` / `员工` / 30 个日期列（表头两行：`星期日` + `2026-11-01`）
- 行：每个员工一行，按岗位分组（管理员 / 收银员 …），未排班的人整行空白

### 3.2 🔴 选完月份不会自动重载

月份选择器只更新输入框的值，**表格仍是上个月**。必须再点一次主按钮 `搜 索`
才发请求重载列头。

- 主按钮选择器：`button.el-button--primary`（**不要**用 `getByRole('button', {name:'搜索'})`，
  按钮文案带全角空格，实际是 `搜 索`，按名字匹配会 30s 超时）
- 校验：`th` 第 3 个应为 `星期日 2026-11-01`、最后一个为 `星期一 2026-11-30`

### 3.3 排班入口：点员工姓名

**点日期格子没有任何反应。** 唯一入口是点 `员工` 列的名字：

| 行号（11 月，本店） | 岗位 | 员工 |
|---|---|---|
| 3 | 收银员 | 员工B |
| 5 / 6 / 7 | 收银员 | 虚拟收银01 / 02 / 03 |

> 行号会随当月人数变化，**不要写死**。用 `tbody tr` 过滤 `innerText` 含目标姓名定位。

点击后弹出 **`排班 - {员工姓名}`** 弹窗：

```
早班：09:00 - 21:00    夜班：21:00 - 09:00
[◀] 2026-11 [▶]        清除当月排班   本月
一 二 三 四 五 六 日
1 [班次 ▾] 2 [班次 ▾] … 30 [班次 ▾]
                        [取 消] [确 定]
```

### 3.4 单元格 = 一个 el-select

- 弹窗里共 **30 个 `.el-select`**，按 1 号→30 号顺序排列
- 选项**只有两个**：`早班`、`夜班`
- **没有「休息」选项**——休息 = 保持空（占位符「班次」），所以"上四休二"的休就是**不填**
- 已排班的日子显示 `早班 ×`，带小叉可直接清除

> ⚠️ 弹窗内的 `清除当月排班` 会把这名员工整月清空，**不可撤销**，脚本里必须用
> `hasText: '取'` 这类精确匹配，绝不能用"按钮索引"点。

### 3.5 保存

点 `确 定` → 弹窗关闭即成功（**无 toast**）。回表格该员工行核对
（显示 `早班(09:00-21:00)` / `夜班(21:00-09:00)`）。

## 四、打卡的两种模式：排班制 vs 自由打卡

> 产品方确认（2026-10-31）。这一节决定「谁能被选成销售人（派送人）」，
> 是员工提成能不能真正落到人头上的**第二道关**（第一道是两个「派送人」开关，见 `13-员工激励.md`）。

### 4.1 两种模式由排班表决定，不由员工选

| 模式 | 谁走这个模式 | 怎么打卡 | 什么时候能被选成销售人 |
|---|---|---|---|
| **排班模式** | 当月**有**排班的 | 按排班表上的班次打上/下班卡 | **当天排了班就在候选里**（打卡只记考勤） |
| **自由打卡模式** | 当月**一天都没有**排班的 | 自己点上班卡 / 下班卡 | **打上班卡后 → 可选；打下班卡后 → 立刻消失** |

> 🔴 **判定权在排班表，不在员工手里**：整月零排班 → 走自由打卡；**只要有一天排了班 → 只能按排班打卡**。
> 排了就回不去，**想切自由打卡必须把整月排班清空**（弹窗里 `清除当月排班`，不可撤销）。

### 4.2 为什么这件事直接影响钱

- 收银台和客户端选销售人时，**列表只列「排了班的人」和「自由打卡已上卡的人」**。
  既没排班、又没上卡的人，根本不在名单里。
- **排班的人靠排班上线，不需要打卡**；只有自由打卡的人才**靠打卡上线**，而且是**一段一段有效**的：
  上卡之前没有人、下卡之后也没有人。漏打上/下班卡，那段时间卖的东西就挂不到人头上。
- 排班模式下的**空班**（排班表上那个格子是空的）= 那个时段没人可接单、也没人可选，
  连占座接单都会受影响（见 `09-门店资料.md` §3.4）。

### 4.3 各家店该怎么选（操作建议）

| 场景 | 建议 | 理由 |
|---|---|---|
| 固定两班倒、店里有 3 人以上 | **排班模式**，月初一次把整月排满 | 覆盖可校验；临时补一天班不会破坏任何东西 |
| 兼职 / 钟点 / 老板本人 / 只有 1~2 人的小店 | **自由打卡模式**，且**整月不给这人排任何班** | 排一天就锁死排班模式，自由打卡失效 |
| 先用了自由打卡、后来想改排班 | 随时可以，**反向不行**（改成排班只需排一天；想退回必须清空整月） | 单向门，先想清楚 |

> ⚠️ 推论（未实测）：**老板自己开单也要提成时，老板本人也必须有在岗身份**
> —— 要么给自己排班，要么走自由打卡打上卡。否则规则里勾了「管理员」，
> 收银台的选人列表里照样没有他。

### 4.4 怎么核实「现在谁算在岗」

1. **考勤明细** `/staffManage/oa/workDays`：列 `员工 / 出勤日 / 班次 / 上班打卡时间 / 下班打卡时间`。
2. 有上卡、**没有下卡** = 人还挂在「在岗」里 —— 既一直能被选，也会一直参与接单。
   夜班下班不打卡是这类脏数据的主要来源。
3. 排班表按 §三 的办法核对整月覆盖，空格子就是没人。

## 五、3 人 / 2 班 / 上四休二 的排法（核心）

### 5.1 先算账，再动手

- 每人 6 天循环里上 4 休 2 → 3 人 × 4 = **12 个班次 / 6 天**
- 每天要 2 个班（1 早 + 1 夜）→ 6 天 × 2 = **12 个班次**

**数量刚好吻合，这意味着"每天必须正好 2 人上班、1 人休息"，一个都不能多。**

由此推出一个反直觉的结论：**三个人的"上四"不能从同一天开始**。
若三人同一天开始上四休二，第 1–4 天会三人同时在岗（第 3、4 天出现 2 早 1 夜），
第 5–6 天则全员休息、**全天无人**。正确做法是每人错开 2 天：

| 循环内第 N 天 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 虚拟收银01 | 早 | 早 | 夜 | 夜 | 休 | 休 |
| 虚拟收银02 | 休 | 休 | 早 | 早 | 夜 | 夜 |
| 虚拟收银03 | 夜 | 夜 | 休 | 休 | 早 | 早 |
| **当天在岗** | 1早1夜 | 1早1夜 | 1早1夜 | 1早1夜 | 1早1夜 | 1早1夜 |

公式（`day` 为当月第几天，从 1 起；`r = (day-1) % 6 + 1`）：

| 人 | r=1,2 | r=3,4 | r=5,6 |
|---|---|---|---|
| 第 1 人（偏移 0） | 早 | 夜 | 休 |
| 第 2 人（偏移 2） | 休 | 早 | 夜 |
| 第 3 人（偏移 4） | 夜 | 休 | 早 |

30 天的月份正好 5 个完整循环：**每人 10 早 + 10 夜 + 10 休**（出勤 20 天 × 12h）。

### 5.2 换人数怎么算

- 需要的人数 = ⌈每日班次数 × 循环天数 ÷ 每人循环内上班天数⌉
  （本例：2 × 6 ÷ 4 = **3 人**，刚好整除）
- 2 人无法覆盖 24h 且满足上四休二（2×4=8 < 12），只能 2 人轮 12h 对倒（上二休二或上二休一）
- 4 人则会富余（16 > 12），要么改成"上四休二但每天多一班"，要么接受部分天 2 人同班

## 六、坑（全部实测踩过）

1. **选月份不重载**，必须点 `搜 索`（见 §3.2）。
2. `getByRole('button', { name: '搜索' })` **超时**——文案是 `搜 索`。用 `button.el-button--primary`。
3. 日期格子点了没反应，**入口是员工姓名**（见 §3.3）。
4. **29 个隐藏下拉干扰选项点击**：点开某天 select 后，DOM 里同时存在 30 个
   `.el-select-dropdown`，只有 1 个可见。用
   `locator('.el-select-dropdown__item', { hasText })` 会先命中隐藏列表里的同名项，报
   `element is not stable` → `element is not visible` → 30s 超时。
   正确做法：`page.evaluate` 里筛 `getBoundingClientRect().height > 5 && offsetParent !== null`
   的**最后一个** popper，再 `li.click()`。
5. **脚本文件只能是单表达式**：`playwright-cli run-code --filename` 把文件当表达式执行，
   顶部写 `const PERSON = 0;` 会报 `SyntaxError: Unexpected token 'const'`。
   常量要写在 `async (page) => { ... }` **内部**。
6. **保存后弹窗关闭 = 成功**，没有 toast，别等提示。
7. 弹窗底部按钮文案带空格：`取 消` / `确 定`，`hasText: '确'` 最稳。
8. 排班弹窗内还有 `清除当月排班` 和 `本月`，误点会毁掉整月数据或跳月，脚本里不要按索引点按钮。
9. **排一天班就把自由打卡废掉了**：整月零排班的人才走自由打卡；随手补一天班，这人就被绑到排班模式，
   **回不去**，除非清空整月排班（不可撤销操作）。
10. **自由打卡模式下漏打下班卡 = 人一直挂在「在岗」**：考勤明细里只有上卡、没有下卡的人会一直出现在
   选人列表里，也一直能接占座单。夜班最容易出这种脏数据。（排班模式不受影响，那种人靠排班表上线。）
11. **上卡前、下卡后选不到人，不是 bug**：自由打卡模式下，销售人列表只在「上卡 ~ 下班卡」这一段有这个人。
12. **排班表上的空格子 = 那个时段没人可选**：不仅提成选不到人，占座接单也没人接。

## 七、脚本

`scripts/set-schedule.js`：

```js
const PERSON = 0;    // 0/1/2 → 表格内第 1/2/3 个目标员工
const SAVE = false;  // false = 只填不存（先看 preview 再存）
```

行为：按 `tr` 定位员工 → 点姓名 → 等弹窗标题含姓名 → 逐个 `el-select` 选值（休息日跳过）
→ 回读 30 天实际值组成 `preview` → `SAVE` 时点 `确 定`。

`preview` 形如 `早 早 夜 夜 - - 早 早 夜 夜 …`，`-` 即休息。**先核对 preview 再存**。

## 八、复核 SQL/接口思路（无接口时用 DOM 断言）

列表页可直接逐格读文本做覆盖校验：

```js
// 每天在 3 人中统计早/夜数量，必须各为 1
const cols = [...]; // 每人 30 天数组，'早'/'夜'/''
for (let d = 0; d < 30; d++) {
  const m = cols.filter(c => c[d] === '早').length;
  const n = cols.filter(c => c[d] === '夜').length;
  if (m !== 1 || n !== 1) bad.push(d + 1);
}
```

`bad` 为空才算真正覆盖满 24 小时。
