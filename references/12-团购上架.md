## 一、四个页面的分工（顺序不能乱）

| 顺序 | 页面 | 路由 | 干什么 |
|---|---|---|---|
| ① | 团购套餐 | `/marketManage/groupManagement/group` | 造券：名称、图片、现金网费 + 赠送网费、适用人群 |
| ② | 上架管理 | `/marketManage/groupManagement/publish` | 选平台、填门市价/团购价/库存，**真正对外可售** |
| ③ | 上架历史 | `/marketManage/groupManagement/putHistory` | 查上架/下架流水 |
| — | 团购授权 | `/marketManage/verificationManagement/groupBuy` | 平台授权（核销管理下，非团购管理） |

**关系：套餐是"货"，上架是"摆上货架"。** 只建套餐不上架 → 列表显示「暂未上架任何平台」，用户买不到。
上架前必须先有套餐，所以「先在团购管理里新增，再到上架页上架」，顺序反了没有可选项。

## 二、① 新建套餐（团购套餐 → 新 增）

实测字段：

实测字段（2026-10-30 二次核对，全量）：

| 字段 | 必填 | 控件 | 默认 | 说明 |
|---|---|---|---|---|
| 套餐名称 | 是 | input | — | 把价格写进名字，如「9.9元享30元网费」，用户一眼看懂 |
| 宣传图片 | **是** | 上传 | — | 750×400 横图。不传不让保存 |
| 套餐详情图片 | 否 | textarea | — | 长图/富文本区，纯网费券可空 |
| 补充信息 | 否 | textarea | — | placeholder「补充信息」，可空 |
| 现金网费 | 是 | number | 空 | placeholder「现金」。**用户实付能当网费用的部分**＝团购价 |
| 赠送网费 | 是 | number | 空 | placeholder「请输入」。`现金 + 赠送 = 券面总额` |
| 有效期设置 | 否 | radio | 相对时间 | 相对时间 / 指定时间；选相对时间时右侧填天数（默认 30） |
| 使用时间限制 | 否 | radio | 全部时间可用 | 全部时间可用 / 部分时间不可用；选不可用要填禁用的时段 |
| 团购使用时间 | 否 | 时间输入 | 00:00:00 | 配合上一项 |
| **使用限制** | 否 | radio | 所有用户 | 所有用户 / 新会员 / 老会员 —— 这就是列表里的「适用人群」 |
| 单人核销次数 | 否 | radio | 不限制 | 不限制 / 限制数量（选限制要填次数） |
| 套餐内容挂载 | 否 | 4 个「选择…」按钮 | — | 核销套餐 / 礼品套餐 / 专场卡 / 商品，纯网费券**不要挂** |

**「仅限新会员」= 把「使用限制」单选到 `新会员`**，不是表单外的开关。上架后列表「适用人群」列会显示「新会员」。

**金额怎么填**（关键，容易填反）：

> 需求「69 块享受 120 网费」→ 现金网费 `69` + 赠送网费 `51` = 120。
> 需求「9.9 块享受 30 网费」→ 现金网费 `9.9` + 赠送网费 `20.1` = 30（带小数时两位相加要精确到角）。
> 列表「套餐内容」列会自动显示成 `69元现金网费+51元赠送网费`，这就是校验点。

**不要点「选择核销套餐」等 4 个按钮。** 纯网费券不需要挂任何内容物，挂了反而限制使用范围。
只需：填名称 → 传图 → 填两个数字 → 保存，返回「添加成功」。

保存后列表「操作」列出现 `编 辑 / 详 情 / 删 除`，说明是本店新建的（系统预置的只有 `详 情 / 删 除`）。

## 三、② 上架到平台（上架管理 → 上/下架）

流程共 **4 次点击**，少一次都不落库：

1. 找到套餐行 → 点「上/下架」→ 弹出**上/下架弹窗**，列出各平台当前状态。
2. 点目标平台行的「上 架」→ 右侧滑出**「套餐上架旺云商城」抽屉**。
3. 填三项必填 → 点抽屉底部「上 架」→ 弹出**确认框**「确认信息无误，请点击提交按钮」。
4. 点确认框的 **「提交」**（⚠️ 不是「确定」）→ 落库。

抽屉字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 门市价格 | 是 | 券面价值（原价），本例 `120` |
| 团购价格 | 是 | 用户实付，本例 `69` |
| 库存 | 是 | **店规：一律 `9999`**，不要自拟 |
| 销售时间 | 否 | 下拉，默认「不限制」，保持默认 |

平台行（本店实测两个）：

- **旺云商城**，服务费 `4‰`，走旺云自有商城，已可上架。
- **美团**，当前未上架；上架前需先在「核销管理 → 团购授权」完成授权，否则点了也上不去。

成功标志：

- 列表「销售平台」列变成 `旺云商城 已上架 团购价：￥69 销售时段： 不限制`；
- 重开上/下架弹窗，平台行 `￥120 / ￥69 / 9999 / 已上架 / 不限制`，操作列变 `下 架 / 详情`；
- 抓包能看到 `POST /business-wy/listInfo/add` 返回 200。

## 四、坑（按踩坑概率排序）

1. **平台行列表偶尔是空的。** 打开上/下架弹窗后平台表格一片空白，不是你点错，是接口没回来。
   处理：关弹窗 → **整页重载** → 重来，最多重试 4 次（`scripts/publish-groupon.js` 已内置）。
   只等待不重载通常也救不回来。
2. **确认框按钮是「提交」不是「确定」。** 按「确定」写脚本会找不到元素，表现为"点了没反应、
   没提示、状态不变"，极容易误判成接口失败。确认框文案：`确认信息无误，请点击提交按钮 / 取消 / 提交`。
3. **点「上 架」后必须先有确认框，才说明按钮真的被点到。** 若连确认框都没弹，是点击没落到按钮上
   （弹窗遮罩/抽屉滚动位置），重试。
4. **只建套餐不上架 = 白干。** 上架管理页里 `暂未上架任何平台` 是默认状态，不是失败。
5. **门市价与团购价别填反。** 填反了用户会看到"原价 69、现价 120"。改法：下架 → 重新上架重填。
6. **库存不要自拟。** 店规统一 `9999`。
7. 本店历史套餐（含预置的）团购价多为 `￥0.01`，那是测试数据，**不要照抄当模板**。

## 五、脚本

`scripts/publish-groupon.js`：只做上架（含平台空表重试 + 提交确认框处理 + 自动复核）。
改顶部常量即可：

```js
const TARGET = '69元享120元网费';  // 套餐名
const PLATFORM = '旺云商城';
const MARKET = '120';   // 门市价
const PRICE = '69';     // 团购价
const STOCK = '9999';   // 店规
const DRY_RUN = false;  // true = 只填不提交
```

新建套餐目前是半手工（名称 + 图片 + 两个金额），脚本未固化——因为宣传图要临时出，
每次金额都不同，固化收益低。照 §二 手工 4 步即可，弹窗只有一个。
