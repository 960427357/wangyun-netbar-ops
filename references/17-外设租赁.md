# 17 · 外设租赁（设备租赁）

> 入口：销售管理 → **设备租赁**（点一次直接落到 `/marketManage/tenancy/statistics`）。
> 进去后有左侧二级菜单：**数据统计 / 设备管理 / 租赁记录 / 租赁设置**。
> 实测门店：示例网咖（连锁 A 店）（2026-10-31）。全店 25 型号 / 99 件在库 + 16 件在租 = **115 件**，
> 租金与押金**全为 0**。

## 一、页面结构

| 页 | 路由 | 关键点 |
|---|---|---|
| 数据统计 | `/marketManage/tenancy/statistics` | 顶部单选：昨天 / 今天 / 最近7天 / 最近一个月 / 最近半年；下方两个日期框 + 「查 询」。KPI 三个：总收入 / 租赁订单 / 利用率。两张表：租赁排行榜（可切「收入 / 利用率」）、分类收入统计 |
| 设备管理 | `.../management` | 表格列：图片 / 名称 / 类别 / **租赁价格** / **押金** / 库存 / 操作（查看·编辑·删除）。图片同样是 ≤500KB，传前 `python scripts/fit-image.py <图> --square --width 600`（铁律 #20） |
| 租赁记录 | `.../log/underLease`、`.../log/finished` | 两个子页「租赁中 / 已完成」。列：租赁编号 / 外设名称 / 用户 / 手机号 / 开始时间 / 租赁时长 / 计费方式 / 租赁费用 / 押金 / 状态 / 创建时间 / 备注 |
| 租赁设置 | `.../setting` | 「添 加 / 保 存」型表单，**没有弹窗**，抓弹窗会抓空 |

二级菜单不是 `el-menu`，是 `div.left-menu-item`（当前页多一个 `active`）：

```js
[...document.querySelectorAll('.left-menu-item')].find(e => e.innerText.trim() === '租赁记录').click()
```

⚠️ 直接 `page.goto('/marketManage/tenancy/log')` 会被**重定向回 `goodsManage/summary`**，
必须从「设备租赁」菜单点进去，再点二级菜单。顶部主菜单同样是自定义 `div.menu-item`。

## 二、四个明文接口

全部是 `POST`，请求体是**加密的 `param`**（服务端解），但**响应是明文 JSON**。
页面内 `fetch` 重放同 `shiftDetail` 一样不可行（缺前端加签），只能「操作页面 → 拦截响应」。

| 接口 | 返回 | 用途 |
|---|---|---|
| `/business-erppro/rentOrder/list` | `{code, count, data[]}` | 租赁明细。`count` 是**总条数**（不是本页条数），`data` 只有当前页 |
| `/business-erppro/rentOrder/statistics` | `{rentIncome, rentOrderNum, timeLength, useRate}` | KPI 三个数 |
| `/business-erppro/rentOrder/getRank` | `data[]` | 排行榜，**最多 5 行** |
| `/business-erppro/rentOrder/statisticsByCategory` | `data[]` | 按分类（鼠标 / 键盘 / 鼠标垫）汇总件次 |

### 2.1 `rentOrder/list` 字段

| 字段 | 含义 | 实测坑 |
|---|---|---|
| `orderNo` | 租赁编号 `GR-yyyyMMddHHmmssNN` | **一个订单多行**，一行一件外设 |
| `id` / `orderId` | 明细 ID / 订单 ID | 去重必须用 `id` |
| `goodsName` | 外设名称 | — |
| `categoryName` | 分类 | **列表接口里经常是空串**，要用「设备管理」的名称→类别映射补 |
| `realName` / `mobile` | 借用人 / 手机号 | 实测 10 条是**空名**，租赁不强制绑会员 |
| `startTime` / `returnTime` | 开租 / 归还 | 在租时 `returnTime` 为空 |
| `status` | `0` = 租赁中 | 字符串 `"0"`，不要用 `if(status)` |
| `price` / `amount` / `deposit` | 单价 / 金额 / 押金 | 全是 `0.0`，全店免费 |
| `billType` / `billUnit` | 计费方式 | 列表里是空串，页面显示「按次数计费」 |
| `timeLength` | 租赁时长 | **列表接口恒为空**，必须自己算 `returnTime − startTime` |

### 2.2 口径（三个都要注意）

1. **`rentOrderNum` 只算已完成，不含在租。** 实测 10-25~10-31 显示 56 单 = 我聚合的 64 单 − 在租 8 单。
   排行榜同理：GPW二代 34 / 神罚75 33 都是「已完成」，把今天的在租加上是 39 / 39。
2. **`timeLength` 单位是「分钟」。** 实测 154,725 ≈ 我用 `returnTime − startTime` 累加的 154,782（差 57 分钟，舍入）。
3. **`useRate` = 已还时长 ÷ (库存 + 在租 件数) × 天数 × 1440。**
   实测 154,725 ÷ (99 + 16) × 7 × 1440 = **13.35%**，与页面完全一致。
   注意分母是「在库 + 在租」而不是「在库」——用 99 算会得 15.5%，对不上。

### 2.3 `getRank` 三个坑

- **只返回 5 行**（型号有 18 个有记录），后面 13 个型号的件次拿不到；
- **不按次数排序**：实测返回顺序 15 / 7 / 33 / 4 / 34；
- **不含在租**，且 `useRate`、`timeLength` 字段都为空——切「利用率」tab 是空表。

做经营分析一律**自己聚合 `list` 明细**，别用这个接口。

## 三、操作要点

### 3.1 筛近 7 天

数据统计页的「最近7天 / 最近一个月」单选是自定义 `.el-radio-button`（不是 `.el-radio`），
`innerText` 里能拿到「最近7天」但点它**不生效**（点完日期框仍是今天）。

**可靠做法：直接改两个日期框**（占位符「开始日期」「结束日期」）：

```js
const inp = page.locator('input[placeholder="开始日期"]').first();
await inp.evaluate(el => el.removeAttribute('readonly'));
await inp.click(); await inp.fill(''); await inp.type('2026-10-25', { delay: 25 });
await page.keyboard.press('Enter');
// 两个都填完后点 body 收面板，再点「查 询」
```

⚠️ 「最近7天」在**已完成列表**里的口径是「**归还时间**落在窗口内」——所以会出现
「10-24 13:14 开租、10-27 10:49 才还」的 69.6 小时订单，按开租时间分组时要单独处理。

### 3.2 翻页与页容量

分页在 `.el-pagination`，文案「共 112 条 100条/页 1 2 前往 页」。
页容量下拉选项 **10/20/30/40/50/100**，切到 100 基本一页装完：

```js
await page.locator('.el-pagination__sizes .el-input, .el-pagination .el-select').first().click();
await page.locator('.el-select-dropdown__item').filter({ hasText: /100/ }).first().click();
```

> 这是**全站通例**（团购券设置、商品明细、核销记录都一样）：列表默认 10 条/页，
> 页脚那串 `10条/页` 是下拉。读全表一律先切 100，别逐页点。
> ⚠️ **切完不记忆**——刷新、重进菜单都回 10 条/页，每次进页都要重切（2026-11-01 实测）。
> 已升为 SKILL.md 铁律 #12，团购券页面的实测数据见 `12-团购上架.md` §10.2。

⚠️ 别用 `page.locator('.el-pager li').filter({hasText:/^3$/})` 连点两页再读表——
实测第二次点击可能没生效，会读到同一页两次（拿到 20 行但其实只有 10+10 重复）。

### 3.3 从「设备管理」拿库存与价格

25 型号，一页 10 条，同样把页容量切到 50 再读。表格文本形如
`GPW二代 鼠标 0/次 ￥0 31 查 看 编 辑 删 除` → 名称 / 类别 / 租赁价格 / 押金 / 库存。

⭐ **「库存」是「可借数量」，在租的已经扣掉了。** 实测 18:05 神罚75 显示 21（当时 6 件在租）、
18:15 显示 20（7 件在租），两次都是 27 件总数。所以：

```
型号总件数 = 当前「库存」 + 当前在租件数      // 两天实测都是 115，恒定
```

全店租金 `0/次`、押金 `￥0`；唯一例外「佳达隆MK60限量款」是 `0元/小时`。

## 五、结论性建议（写死，不用再推）

1. **先补价格**：5 个主力款（GPW二代、神罚75、GPW五代雪豹、雷电75、雷蛇毒蝰V3pro）配 2 元/次 + 20 元押金，
   跑一周看交接班「租赁统计」是否出现金额。
2. **按次而不是按小时**：单均 22 h、74% 跨夜，按时计费算不清；用「2 元/次 + 满 4 小时免费续」
   或「首日 5 元 / 加一天 3 元」。
3. **必须绑会员**：10 条空名记录意味着丢件找不到人。
4. **鼠标垫并进套装**（借键鼠送垫），把 12 件闲置库存盘活成赠品。
5. **加超时提醒**：最长 69.6 h，系统不提醒，等于没人管。

## 六、坑清单

| 坑 | 表现 | 处理 |
|---|---|---|
| 直接 goto 子页 | 被重定向回 `goodsManage/summary` | 从菜单点 |
| 点「最近7天」单选 | 日期不变，查询结果还是今天 | 直接改两个日期框 |
| `getRank` 当排行榜用 | 只有 5 行、不排序、缺在租 | 自己聚合 `list` |
| 用 `categoryName` 分类 | 列表接口常为空串 | 用设备管理名称→类别映射 |
| `timeLength` 当小时 | 值是 154725 | 单位是**分钟** |
| `useRate` 反推库存 | 99 件算不出 13.35% | 分母 = 库存 + 在租 |
| 连点两个页码 | 读到重复页 | 切 100 条/页一次读完 |
| 在租记录当已还 | `returnTime` 为空却算时长 | 先判空 |
