# 旺云商户端 · 员工与权限配置技能手册 v2

> 路由前缀 `/staffManage`，门店「演示门店」。
> 状态：2026-10-29 实测。v1 只抓字段不落库；v2 已实际补建 5 个部门并验证联动。
> 用途：新增员工、配权限、算提成、查考勤。
> **控件库是 Element Plus（Vue 3），不是 Element UI**，选择器差异见 §九。

---

## 一、结论先行

1. 员工体系是**五层**：部门 → 岗位（含班次）→ 角色（权限）→ 员工 → 绩效/激励/打赏/OA。**必须先建前四层，才能加员工**。
2. 「岗位」和「角色」不是一回事：**岗位管班次与业务归属，角色管系统权限**。员工同时挂两者。
3. 角色内置 7 个：管理员 / 平账 / 店长 / 收银员 / 保洁员 / 推销员 / 股东。权限靠「权限配置」按钮逐项勾。
4. 提成有三种算法（固定提成 / 销售额提成 / 销售总额提成），选错算法出来的钱差很远，配置前先跟老板确认口径。

## 二、配置顺序

```
① 部门管理  建组织结构（前台/保洁/技术…）
      ↓
② 岗位管理  建岗位 + 班次时间（早班 08:00-16:00…）
      ↓
③ 角色管理  建角色 + 权限配置（能看哪些模块、能改哪些数据）
      ↓
④ 员工管理  手机号 + 密码 + 岗位 + 角色 + 部门
      ↓
⑤ 绩效任务 / 激励规则 / 打赏设置 / OA排班
```

## 三、① 部门管理 `/staffManage/department`

列表列：部门 / 人数 / 主管 / 操作。按钮：搜 索 / 清 空 / 新 增。
行操作：编 辑 / 删 除。

新增弹窗标题「新 增」，只有两个字段：

| 字段 | 必填 | 控件 | 说明 |
|---|---|---|---|
| 部门 | **是** | 文本框 | placeholder「请输入 部门名称」 |
| 主管 | 否 | 下拉 | 选项 = 员工列表，格式 `昵称(手机号)`，如 `员工C(19900000005)`；员工为空时该项选不了 |

「人数」是自动统计的，不用手填；未挂人的部门显示 `0`。
「主管」留空完全合法，弹窗只有「保 存 / 取 消」两个按钮。

**联动已验证**：员工管理 → 新增 → 「部门」下拉已能选到这 5 项，说明部门一建就能被员工引用。

### 3.2 建多少、怎么命名

按网吧实际岗位拆，别按「职务等级」拆（等级归角色管）：

| 部门 | 装谁 |
|---|---|
| 店务管理 | 店长、值班经理、股东（看数据为主） |
| 前台收银 | 收银、开卡、结账、交接班 |
| 网管技术 | 网管、维修、机房与监控 |
| 吧台出品 | 水吧、简餐、商品售卖 |
| 保洁 | 清台、公区卫生 |

部门只影响统计口径和排班归属，不影响权限；**权限永远由角色决定**（§五）。

### 3.3 常见错误

- **部门名带班次**（如「收银早班」）：错。班次属于岗位管理，部门只按职能拆。
- **重复建同名部门**：后台不拦重名，会并存两条，统计被打散。脚本已做「已存在则跳过」。
- **先删部门再删员工**：反了。有人的部门删不掉或带走历史统计，先停用/删员工。

## 五、③ 角色管理 `/staffManage/role`

列表列：# / 名称 / 别名 / 排序。按钮：搜 索 / 清 空 / 新 增 / 编 辑 / 删 除 / **权限配置**。

新增弹窗字段：名称（请输入 角色名称）、别名（请输入 别名）、排序（请输入 排序）。

### 内置角色

管理员 / 平账 / 店长 / 收银员 / 保洁员 / 推销员 / 股东

### 权限配置怎么配

选中角色 → 点「权限配置」→ 勾模块与操作。判据：

- 收银员：只给收银台、商品、会员查询，不给计费设置和财务。
- 店长：给经营数据 + 员工排班，不给钱包提现。
- 股东：只给报表与流水，只读。
- 保洁员 / 维修工：只给 OA 打卡与服务呼叫。

**权限改动后必须让员工退出重登**，否则按旧权限跑。

## 七、⑤ 绩效任务 `/staffManage/netbarPerformance/taskSetting`

列表列：任务名称 / 触发条件 / 奖励积分 / 参与岗位 / 状态。

### 7.1 派发任务（手动派发）`.../taskList`

三个 tab 是同级标签：**任务设置｜派发任务｜积分统计**，都在员工绩效下。

筛选：责任人（下拉，选项＝全部员工昵称）／状态。按钮：**搜 索 / 清 空 / 新 增**。

列表列：任务名称 / 奖励积分 / **参与岗位** / **责任人** / 状态 / 派发时间 / 完成时间 / 现场照片。

**新增弹窗「手动派发任务」（4 项，实测 2026-10-31）**

| # | 字段 | 控件 | 说明 |
|---|---|---|---|
| 0 | 任务名称 | 文本 | 必填 |
| 1 | 奖励积分 | 文本 | 数值，普通任务 1~5 分 |
| 2 | 参与类型 | **单选二选一** | `指定岗位` / `指定责任人` |
| 3 | 参与岗位 **或** 责任人 | 复选框 / **单选** | 随第 2 项切换：选「指定岗位」出四岗位多选；选「指定责任人」出**全部员工单选** |

🔴 **责任人是单选（radio），一条任务只能派给一个人。** 想让多人都做，只能建多条任务，
或改用「指定岗位」（但岗位任务是广播给当班员工，谁抢到算谁的）。

🔴 **「指定责任人」的任务落库后状态直接是「处理中」，不是「待接单」**；
「指定岗位」的任务才是「待接单」，等人抢。列表的「参与岗位」列在按人派发时为空。

⚠️ 定位坑：`filter({hasText:'责任人'})` 会同时命中「参与类型」那一项（因为里面有「指定**责任人**」三个字），
必须改成按 label 文本取索引：

```js
const idx = await items.evaluateAll(els => els.findIndex(e =>
  ((e.querySelector('.el-form-item__label')?.innerText)||'').replace(/\s+/g,'').startsWith('责任人')));
```

### 7.2 积分统计 `.../pointList`

列：责任人 / 分店 / 岗位 / 积分 / 完成任务 / 操作。筛选只有「日期」。
**积分只是排名用的绩效分，不能折算成钱**——要发钱仍得走「员工激励/提成」或「员工打赏」。

### 7.3 已完成任务的现场照片

列表有「现场照片」列，即员工完成任务时要上传照片（客户端侧操作）。

## 八、⑥ 员工激励 `/staffManage/staffCommission/currRules`

列表列：规则名称 / 适用场景 / 提成方式 / 计算提成周期 / 生效时间 / 结束时间 / 参与岗位 / 参与商品|分类|团购套餐。

筛选：参与商品|团购套餐。按钮：新 增 / 推销情况 / 作废 / 查看。

新增弹窗「新增提成规则」字段：

| 字段 | 选项 |
|---|---|
| 规则名称 | 请输入 规则名称 |
| 适用场景 | **商品推销 / 会员拉新 / 会员充值 / 旺云团购** |
| 提成方式 | **固定提成 / 销售额提成 / 销售总额提成** |
| 提成金额 | 请输入 提成金额 |
| 计算提成周期 | **每日 / 自然月 / 有效期** |
| 生效时间 / 结束时间 | 请选择 |
| 参与岗位 | 管理员 / 保洁员 / 维修工 / 收银员 |

三种提成方式的区别：

- 固定提成：卖一件给固定金额，适合标准化商品。
- 销售额提成：按单笔销售额比例，适合客单价差异大的。
- 销售总额提成：按周期总销售额比例，适合冲量激励。

**「每日」周期 + 「销售总额提成」组合会产生每天结算一次总额提成**，长周期活动要选「有效期」。

配套：提成结算 `.../settlement`、历史规则 `.../historyRules`。

## 十、⑧ OA `/staffManage/oa/*`

**考勤明细** `/staffManage/oa/workDays`：列 员工 / 出勤日 / 班次 / 上班打卡时间 / 下班打卡时间。筛选 员工、日期。

**排班** `/staffManage/oa/scheduling`：按岗位班次排到人。

### 打卡两种模式（决定「在不在岗」，进而决定能不能被选成销售人）

| 模式 | 谁 | 打卡方式 | 何时可被选成销售人 |
|---|---|---|---|
| 排班模式 | 当月**有**排班 | 按排班班次打上/下班卡 | 按排班在岗期间 |
| 自由打卡模式 | 当月**一天都没**排班 | 自己点上班卡 / 下班卡 | **上卡后可选，下卡后消失** |

> 🔴 模式由**排班表**决定，不是员工选：排一天班就锁死排班模式，回不去。
> 🔴 收银台与客户端的选人列表**只列在岗的人**，所以「没排班 = 选不到 = 没提成」。
> 详见 `15-排班与班次.md` §四、`13-员工激励.md`「前置两关」。

## 十一、通知设置联动

`/admin/systemSetting/staffNotice`：列 岗位名称 / 消息通知类型 / 操作，按钮「配置」。
这里控制**哪个岗位收到哪类通知**（如收银员收新订单、保洁收呼叫）。新增岗位后要回来补一条，否则那人收不到提醒。

### 11.1 五种通知类型（2026-11-02 实测）

配置弹窗只有两个字段：`岗位名称`（只读）+ `消息通知类型`（多选复选框），按钮「保 存」。

| 通知类型 | 触发场景 |
|---|---|
| 占座接单通知 | 客人预约占座，需前台接单 |
| 网民购买商品通知 | 客户端下单买商品 |
| 上机余额不足通知 | 会员余额将尽 |
| 呼叫退租通知 | 客户呼叫 / 退租 |
| **商超补货通知** | 🔴 **库存预警的唯一 APP 入口**——商品/原料库存跌破阈值时推给该岗位 |

**商超补货通知就是库存预警的口子。** 库存预警页（`baseManage/warning`）配的是「什么物件、阈值多少」，
通知设置配的是「**提醒推给谁**」。两边都配齐才会收到推送，只配一边等于没配。

### 11.2 关键约束：按岗位推送，不能指定单人

- 通知挂在**岗位**上，不挂在人上。给「收银员」勾上，该岗位下**全部账号**都会收到。
- 想只让某一个人收到，只能**给这个人单独建岗位**（岗位管理里新增，如「库管」），再单独勾。
- 改岗位 → 该岗位下所有人的接收范围同时变化，没有例外。

实测现状（南充测试场所，8 个账号）：

| 岗位 | 人数 | 账号 |
|---|---|---|
| 管理员 | 3 | 黎云 13096139613、002 19161313306、王国栋 15983757838 |
| 收银员 | 5 | 收银01/02/03、**旺旺吧代管账号 18060783837**、菜鸡 17761182676 |
| 保洁员 / 维修工 | — | 空，默认无通知 |

🔴 **「旺旺吧代管账号」的岗位是收银员，不是管理员。** 按手机号找人时别想当然——
先去 `员工管理`（`/staffManage/mgr`）查该号码对应的**岗位**列，再去对应岗位勾权限。

### 11.3 保存接口

| 项 | 值 |
|---|---|
| 接口 | `POST /business-merchant/businessPlacePosition/setReceiveNotice` |
| 成功返回 | `code 200` / `message 操作成功` |
| 弹窗行为 | 点「保 存」即关闭，**没有二次确认** |
| 回读方式 | 列表的「消息通知类型」列变成顿号连接的中文名（如「占座接单通知，网民购买商品通知，商超补货通知」），`--` 表示一条都没勾 |

**勾选控件**：`el-checkbox`，判据 `className.indexOf('is-checked') >= 0`。
点 label 本体即可（原生点击会转发到内部 input），不要直接点隐藏的 `input`。

**改完要回读列表确认**：弹窗关闭只代表交互结束，不代表写库成功。

## 十二、校验清单

| 检查项 | 期望 |
|---|---|
| 员工是否挂了角色 | 没角色登不进 |
| 员工是否挂了部门 | 没部门则部门人数恒 0，按部门的统计全空 |
| 岗位是否有班次 | 没班次排不了班 |
| 打卡模式是否符合门店 | 固定班排班、兼职/老板走自由打卡（条件：整月零排班），否则收银台选不到人 |
| 角色权限是否越界 | 收银员不应看到计费设置与钱包提现 |
| 提成规则场景与周期是否匹配 | 每日 + 总额提成易算错 |
| 通知设置是否覆盖新岗位 | 新岗位默认无通知 |
| 库存预警有没有人收 | 预警记录配了之外，还要在通知设置给**接收人所在岗位**勾「商超补货通知」，否则只存不发 |
| 员工离职处理 | 先停用/删员工，别直接删部门，会带走统计 |

## 十三、选择器与控件库（Element Plus 实测）

本站是 **Vue 3 + Element Plus**，不是 Vue 2 + Element UI。写脚本时按 Plus 的结构取：

| 目标 | 正确写法 | 踩过的坑 |
|---|---|---|
| 弹窗容器 | `.el-dialog`，可见性判 `offsetParent !== null` | **没有 `.el-dialog__wrapper`**（那是 Element UI 的），用了会取到空 |
| 弹窗遮罩 | `.el-overlay` | — |
| 下拉本体 | `.el-select`（内含 `.el-select__wrapper`） | `el-select--default` 是 Plus 的默认尺寸类 |
| 下拉选项 | `.el-select-dropdown__item` | 多个下拉的选项在 DOM 里并存，要取**当前可见**的 dropdown |
| 复选框组 | `.el-checkbox-group` + `.el-checkbox__label` | 角色是复选框不是 select |
| 输入框赋值 | 原生 `input.value = v` + 派发 `input`/`change` | 直接 `fill()` 也可，但批量循环里原生事件更快 |

**可见性过滤写法**（本包脚本统一用）：

```js
const ds = [...document.querySelectorAll('.el-dialog')].filter(d => d.offsetParent !== null);
const dlg = ds[ds.length - 1];   // 取最后一个可见弹窗，避免历史弹窗干扰
```

**选项读取写法**：

```js
const open = [...document.querySelectorAll('.el-select-dropdown')].filter(d => d.offsetParent !== null);
const box = open[open.length - 1];
[...box.querySelectorAll('.el-select-dropdown__item')].map(li => li.innerText.trim());
```

若把全页 `.el-select-dropdown__item` 一把抓，会把分页条（10条/页…）和其他下拉的选项混进来——
曾经因此把「部门下拉」读成了 19 项杂项，实际只有 5 项。
