# 旺云商户端 · 上架到吧台（纯移库）技能手册 v2

> 站点 wyb.5188cloud.net，门店「演示门店」。
> v1 误把「补货」当成纯上架，实际会同时入库，导致总库存虚增。本版已按实测流水更正。
> 状态：2026-10-29 实测，含一次误操作与一次纠错记录。

---

## 一、结论先行

1. 「补货」弹窗做不了纯上架。它的「数量」= 入库，会独立写一条入库流水。
2. 纯上架（把仓库现有货搬到吧台，总库存不变）要用商品管理表格里的两个内联库存框直接改。
3. 判断标准：纯上架后 默认吧台库存 +N、未出货 −N、总库存不变。只要总库存变大了，就是混进了入库。

## 二、补货弹窗的真实语义（有流水为证）

| 字段 | placeholder | 真实含义 | 流水影响 |
|---|---|---|---|
| 数量（必填） | 请输入单件商品的库存量 | 本次入库数 | 未出货 +N，独立一条流水 |
| 上架吧台 | 请输入数量 | 从入库中出货到吧台 | 吧台 +N、未出货 −N，独立一条流水 |

两个都填 N 时，系统写两条流水，等于「入库 N + 上架 N」，总库存凭空 +N。这是本次踩的坑。

实测证据（库存历史数据，2026-10-29 22:12:08，两条同一秒）：
- 吧台 100→100，未出库 90→110（入库 +20）
- 吧台 100→120，未出库 110→90（上架 +20）
净结果：吧台 120、未出货 90、总库存 210。原总库存 190，虚增 20。

## 三、纯上架到吧台 的正确做法

目标：吧台 +N，未出货 −N，总库存不变。

1. 销售管理 → 商超管理 → 商品管理（`/marketManage/goodsManage/shop/goods`）
2. 商品名称搜索，定位目标行（同款不同规格用精确名称）
3. 直接改表格内联库存框
   - 默认吧台库存：原值 + N
   - 未出货：原值 − N
4. 输入后按 Tab 失焦，系统自动保存（无需弹窗、无需点保存）
5. 刷新页面校验：吧台 +N、未出货 −N、总库存不变

实测：把未出货内联从 90 改成 70，按 Tab 失焦，刷新后仍为 70，并在 22:19:54 写入流水「吧台 120→120，未出库 90→70」。证明内联框可编辑、会落库、会记账。

注意：商品管理里 默认吧台库存、未出货 两个内联框只读属性均为 false，可直接编辑。

## 四、误操作的纠错流程

若误用补货导致总库存虚增 N（吧台多 N、未出货也多记 N 的效果）：

1. 打开 库存历史记录，确认是「入库 N」那条造成的。
2. 到商品管理，把该商品 未出货 内联值减去 N，Tab 失焦保存。
3. 刷新复核，总库存应回落到原值。

本次纠错：未出货 90→70，总库存 210→190，吧台保持 120，符合「上架 20 到吧台」的真实结果。

## 五、校验清单（每次必看）

| 场景 | 默认吧台库存 | 未出货 | 总库存 |
|---|---|---|---|
| 纯上架 N | +N | −N | 不变 |
| 纯入库 N | 不变 | +N | +N |
| 误用补货（两个都填 N） | +N | 不变 | +N（错，需纠错） |

任一与预期不符，立即停下，不要连续操作。

## 六、易错点

- 补货弹窗两个数量框 placeholder 不同，是区分二者的唯一稳定依据。
- 同款多规格（如「康师傅冰红茶」与「康师傅冰红茶 1L」）必须用 exact 精确匹配，否则点错行。
- 库存历史记录只读，不能删改，纠错只能靠反向调整账面。
- 内联框改完必须刷新复核，确认真的落库。

## 七、脚本

`scripts/replenish.js` 已改为纯上架模式：读取该行现有 默认吧台库存 与 未出货，改为 +N / −N，失焦保存，再刷新校验。默认 DRY_RUN 只读不改。

```bash
playwright-cli run-code --filename ./scripts/replenish.js
```
