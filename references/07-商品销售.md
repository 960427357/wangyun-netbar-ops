## 一、结论先行

1. 商超是三层：**基础管理（主档）→ 商品管理（库存与销售）→ 团购/核销（线上渠道）**。主档没建，商超里没有商品可卖。
2. 主档顺序：**商品分类 → 商品名称 → 计量单位 → 吧台设置 → 标签设置 → 库存预警**。分类为空时新增商品存不进去。
3. 库存有四个数：默认吧台库存、未出货、总库存、以及各吧台分库存。**纯上架只动前两个，不动总库存**（这是踩过的坑）。
4. 核销收入有两种统计口径（平台展示价 / 订单交易价），选错会让账面和平台对不上。

## 二、商超管理 `/marketManage/goodsManage`

三级页面（内层 tab）：总览 / 商品管理 / 基础管理。

### 2.1 商品管理的七个 tab

| Tab | 路由片段 | 用途 |
|---|---|---|
| 商品管理 | `shop/goods` | 主表：库存、价格、补货、报损、上下架 |
| 套餐管理 | `shop/goodsPackage` | 组合销售 |
| 销售总览 | `shop/goodsSale` | 销售统计 |
| 商品报损 | `shop/goodsDestory` | 损耗登记 |
| 盘点记录 | `shop/stockHistory` | 盘点流水 |
| 点货记录 | `shop/barStockHistory` | 吧台点货 |
| 原料管理 | `shop/rawMaterial` | 原料与配方 |

商品管理主表的关键行为（实测）：

- 搜索框 placeholder `请输入商品名称`，按钮「搜 索」。
- 行内按钮：补货 / 编辑 / 报损 / 库存历史记录 等。
- **默认吧台库存、未出货 是可编辑内联框，失焦即存**，没有保存按钮。
- 同款多规格（如「康师傅冰红茶」与「康师傅冰红茶 1L」）必须用精确名称匹配，否则改错行。

### 2.2 基础管理的六个 tab

| Tab | 路由 | 用途 | 关键列 |
|---|---|---|---|
| 商品分类 | `baseManage/goodsCate` | 分类树 | 分类名称 / 排序 / 图片 |
| 商品名称 | `baseManage/goodsName` | 主档（实测 149 条） | 商品名称 / 图片 |

| 标签设置 | `baseManage/tagsSet` | 分类标签 | 标签名 |
| 库存预警 | `baseManage/warning` | 阈值 + 短信 | 类别名称 / 最低阈值 / 状态 / 短信预警 / 商品名称 / 材料名称 |

**商品分类新增弹窗（标题「添加分类」）**：

| 字段 | 说明 |
|---|---|
| 商品分类名称 | 请输入商品分类名称 |
| 排序 | 请输入排序 |
| 分类图片 | 上传 |

**库存预警**：按钮「保 存 / 添加」，列同时兼容「类别」「商品名称」「材料名称」三类对象，阈值按对象配，可开短信预警。

**吧台设置**：按钮「添加 / 编辑」，列 吧台名称 / 说明。多吧台（前台吧台、二楼吧台）在这里建，商品补货时选目标吧台。

## 三、核销管理 `/marketManage/verificationManagement`

| 页面 | 路由 | 用途 |
|---|---|---|
| 团购授权 | `groupBuy` | 平台授权 |
| 团购券设置 | `groupSet` | 券面配置 |
| 核销记录 | `gruopWriteOff` | 流水（**平台拼写错误，照抄**） |
| 核销总览 | `summary` | 汇总 |
| 团购互斥组 | `groupMutex` | 互斥规则 |
| 核销设置 | `writeOffSet` | 全局开关 |

**核销设置**字段（保存生效）：

| 字段 | 选项 |
|---|---|
| 撤销自动审核 | 是 / 否 |
| 核销收入统计方式 | **按平台展示价格 / 按订单交易价格** |

口径差异：平台常有「团购价 39.9，门店标价 58」的情况，选「平台展示价」按 39.9 记收入，选「订单交易价」按实际结算记。**跟财务确认一次，别两边都改**。

## 五、设备租赁 `/marketManage/tenancy`

四页：数据统计 `statistics` / 设备管理 `management` / 租赁记录 `log`（租赁中 `underLease`、已完成 `finished`）/ 租赁设置 `setting`。

租赁设置页是「添 加 / 保 存」型表单，无弹窗——脚本抓弹窗会抓空，属正常。

## 六、异常订单 `/marketManage/orderManagement`

| 页面 | 路由 | 按钮 |
|---|---|---|
| 未处理 | `pending` | 搜 索 / 清 空 / **已处理** / **退款** |
| 已处理 | `processed` | 查询类 |

未处理列表列：订单来源 / 内容 / 充值金额 / 下单时间 / 姓名 / 证件号。筛选：下单时间、姓名、证件号。

**「退款」是真实资金动作**，点之前必须核对姓名 + 证件号 + 金额，且要确认订单来源（美团/抖音/支付宝）。

## 七、典型流程

### 7.1 新品从零上架

1. 基础管理 → 商品分类：新建分类（名称 + 排序 + 图片）
2. 基础管理 → 商品名称：添加商品名称（**这里只填名称 + 图片，无价格**）
3. 基础管理 → 计量单位：确认单位存在
4. 基础管理 → 吧台设置：确认目标吧台
5. 商品管理 → 搜商品 → 补货（数量 = 入库数，上架吧台 = 出货到吧台数）
6. 商品管理 → 行内改「销售价 / 进货价 / 积分」
7. 基础管理 → 库存预警：设最低阈值

### 7.2 已有商品补货上吧台

见《08-补货上架.md》。核心：补货弹窗两个数量框含义不同，`数量` = 入库（加总库存），`上架吧台` = 从入库出货到吧台。

### 7.3 接团购单

1. 团购管理 → 团购套餐：建套餐（有效期 + 使用限制 + 单人核销次数）
2. 团购管理 → 上架管理：推到渠道
3. 核销管理 → 核销设置：确认收入统计口径
4. 日常：核销管理 → 核销记录 对账，异常订单 → 未处理 处理退款

## 八、红线

- **改库存有账**：所有库存变动都会写库存历史，写错只能反向调，删不掉。
- **补货 ≠ 上架**：两个数量框填成一样会导致总库存虚增（已踩过）。
- **核销口径只改一次**：改口径会让历史统计断层。
- **退款不可逆**：核对三要素后再点。
- **商品原价与促销价分开**：打折走商品促销，不要改主档销售价。

## 九、校验清单

| 检查项 | 期望 |
|---|---|
| 分类是否已建 | 空分类无法加商品 |
| 商品是否有价格 | 主档只存名称，价格在商品管理行内 |
| 补货后总库存是否合理 | 纯上架总库存不变 |
| 多规格是否命中正确行 | 用精确名称 |
| 核销口径是否与财务一致 | 平台展示价 vs 订单交易价 |
| 套餐单人核销次数 | 不限制容易被刷 |
