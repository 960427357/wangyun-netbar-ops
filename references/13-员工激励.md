## 二、⚠️ 先看这个：两个名字几乎一样的提成方式，算出来差一倍

这是本模块**最容易配错、损失最大**的地方。系统内嵌了官方算例，我原样抄下来：

设阶梯配成 100→10%、200→15%、300→20%，销售额 260 元：

| 提成方式 | 算法 | 260 元算出 | 500 元算出 |
|---|---|---|---|
| **销售额提成** | **分段累进**（像个人所得税） | `(200-100)×10% + (260-200)×15%` = **19 元** | `10+15+40` = **65 元** |
| **销售总额提成** | **全额跳档**（够档就整笔乘） | `260×15%` = **39 元** | `500×20%` = **100 元** |

同样一条阶梯，**260 元时差 20 元（一倍多），500 元时差 35 元**。

- 想要「多卖多提、但只对超额部分加速」→ 选 **销售额提成**。
- 想要「冲到这个档位，全月都按高档提」→ 选 **销售总额提成**（成本高得多）。

**配置前必须跟老板确认这一句**：「超出部分按比例」还是「达到就整笔按高档」。选错了，月底对账一定吵。

## 三、提成方式矩阵（跟场景联动，不是固定四选一）

**这一条文档里从来没写过**：能选哪些提成方式，取决于先选了哪个「适用场景」。

| 适用场景 | 可选提成方式 | 备注 |
|---|---|---|
| 商品推销 | 固定提成 / 销售额提成 / 销售总额提成 | 可指定商品范围 |
| **会员拉新** | **只有「固定提成」** | 不能按比例，只能按人头给固定金额 |
| 会员充值 | 固定提成 / 销售额提成 / 销售总额提成 / **单笔充值提成** | 唯一能用「单笔充值提成」的场景 |
| 旺云团购 | 固定提成 / 销售额提成 / 销售总额提成 | 可指定套餐 |

所以：**先选场景，再看能选什么方式。** 顺序反了会发现选项对不上。

## 四、四种算法详解

### 1. 固定提成

字段变回 **「提成金额」**，单位 `元`。

```
【请输入 提成金额】元
```

每成交一单给固定金额。适合标准化商品（卖一桶泡面给 1 元）。

**适合**：商品单价稳定、想简单粗暴激励。
**风险**：卖 1 元的东西也给同样钱，亏本。

### 2. 销售额提成 —— 分段累进

字段变成 **「提成规则」**，是一个可加 100 行的阶梯表：

```
销售额累计超过【X】元部分，提成【Y】%    [删除]
+ 添加（最多添加 100 条）
```

官方算例（原样保留，这是理解算法的唯一准确依据）：

> 销售额累计超过 100 元部分，提成 10%；100(不含)-200(含) 元之间的这部分提 10%
> 销售额累计超过 200 元部分，提成 15%；200(不含)-300(含) 元之间的这部分提 15%
> 销售额累计超过 300 元部分，提成 20%；超过 300 元的这部分提 20%
>
> 500 元 → `(200-100)×10% + (300-200)×15% + (500-300)×20% = 65`
> 260 元 → `(200-100)×10% + (260-200)×15% = 19`
> 150 元 → `(150-100)×10% = 5`
> 没超过 100 元 → 不提成

**第一档的门槛是「起征点」，不是「第一段」**：配「超过 100 元部分提 10%」时，卖 150 只提 (150-100)×10%=5，**前 100 元一分不提**。

### 3. 销售总额提成 —— 全额跳档

同样是阶梯表，但文案不同：

```
销售总额达到【X】元，提成【Y】%    [删除]
```

官方算例：

> 达到 100 元(含) 提 10%；达到 200 元(含) 提 15%；达到 300 元(含) 提 20%
>
> 500 元 → `500×20% = 100`
> 260 元 → `260×15% = 39`
> 150 元 → `150×10% = 15`
> 少于 100 元 → 不提成

**够到哪一档，整笔都乘那一档的比例**。阶梯行数越多，成本越高，因为它总按最高满足档算。

### 4. 单笔充值提成 —— 只在「会员充值」场景出现

**空态只有「+添加」按钮，没有任何文案提示**，加了行才看得见结构：

```
单次充值满【X】元，提成【Y】元    [删除]
```

官方算例（注意最后一条，这是套利口子）：

> 单次充 200（含）→ 提 2 元
> 单次充 300（含）→ 提 3 元
> 单次充 500（含）→ 提 6 元
> 单次充 400 → 未达 500 档，仅满足 300 档，提 **3 元**
> **分两笔各充 200（合计 400）→ 分两单核算，每单各提 2 元，合计 4 元**

**它按「单笔」算，不按「累计」算。** 顾客把 400 拆成两笔 200，员工多拿 1 元；拆得越多拿得越多。
如果配了「充 500 提 6 元」这种大额档，员工会主动教顾客拆单，直接吃掉大额奖励。**要么别配大额档，要么配成销售额提成。**

## 五、新增弹窗字段（8 项，动态变化）

弹窗宽 800px，标题「新增提成规则」，底部只有 `保存` / `取消`。

| 字段 | 必填 | 控件 | 随什么变 |
|---|---|---|---|
| 规则名称 | 是 | 文本，**上限 50 字**，实时显示 `0 / 50` | — |
| 适用场景 | 是 | 单选：商品推销 / 会员拉新 / 会员充值 / 旺云团购 | 决定后面能选什么 |
| 提成方式 | 是 | 单选：固定提成 / 销售额提成 / 销售总额提成（会员充值多一个单笔充值提成） | **选项随场景变** |
| 提成金额 **或** 提成规则 | 是 | 固定提成→金额输入框（元）；其余三种→阶梯表（+添加，最多100条） | **字段本身会换名换控件** |
| 计算提成周期 | 是 | 单选：每日 / 自然月 / 有效期 | — |
| 生效时间 | 是 | 日期时间选择器 | — |
| 结束时间 | 是 | 日期时间选择器 | — |
| 参与岗位 | 是 | 复选：管理员 / 保洁员 / 维修工 / 收银员（多选） | — |
| 参与商品： | 仅商品推销 | 下拉：指定商品 / 指定分类 / 全店商品 | 选了「指定商品」才出现「选择商品」按钮 |
| 团购套餐 | 仅旺云团购 | 下拉（**必填**）：指定套餐 / 全部套餐 | — |

**「计算提成周期」的三种语义：**

- **每日**：每天算一次，当天清零。适合日结小激励。
- **自然月**：整月累计，月底算。适合阶梯提成（阶梯要靠累计才爬得上去）。
- **有效期**：按规则的生效→结束整段算。

**坑：选「每日」+ 阶梯提成 = 每天从 0 开始爬阶梯。** 如果目的是「月销 5000 提 10%」，周期必须选「自然月」，否则永远只爬到第一档。

### 🔴 规则 1 有重大问题，建议立刻核对

它配的是「**超过 1 元的部分提 50%**」，全店商品、每日、收银员。按这个算：

| 卖出去的东西 | 员工提成 |
|---|---|
| 3 元可乐 | (3-1)×50% = **1 元**（毛利基本给光） |
| 10 元泡面+饮料 | (10-1)×50% = **4.5 元** |
| 日销 500 元商品 | (500-1)×50% = **249.5 元/天** |

一个吧台日销 500 元很常见，按这条规则一天要发 **249.5 元**提成，一个月 **7485 元**。

**基本可以断定是误操作，证据是历史记录：**

> 同名的旧规则「商品推销」是 **销售总额提成 + 自然月 + 提成 2%**，
> 2026-10-08 **16:15:23** 被作废；**13 分钟后的 16:17** 建了现在这条
> **销售额提成 + 每日 + 提成 50%**。

从 2% 改到 50%，**翻了 25 倍**，同时把「自然月」改成了「每日」、把「总额跳档」改成了「分段累进」。
三个维度同时改且数值离谱，不像有意调整，更像填错格子（把「50」当成别的口径填进了百分比）。
**建议立刻找老板确认真实口径，确认前先作废这条规则，否则每天都在产生提成债务。**

## 十一、坑清单

| # | 坑 | 后果 / 对策 |
|---|---|---|
| 1 | 销售额提成 vs 销售总额提成名字太像 | 260 元时差 19 vs 39 元。配错必吵，先确认口径 |
| 2 | 提成方式选项随场景变 | 会员拉新只有固定提成；单笔充值提成只在会员充值。先选场景 |
| 3 | 「提成金额」和「提成规则」是**两个不同字段** | 切方式时字段会换名换控件，别照着模板填 |
| 4 | 单笔充值提成按单笔算 | 拆单套利：400 拆两笔 200，提成从 3 变 4 元 |
| 5 | 第一档门槛是起征点 | 「超 100 提 10%」时卖 150 只提 5 元，前 100 不提 |
| 6 | 每日 + 阶梯 = 阶梯永远爬不上去 | 想按月冲量必须选「自然月」 |
| 7 | 单笔充值提成空态只有「+添加」，无任何文案 | 不点添加看不出结构，容易以为坏了 |
| 8 | 「查看」弹窗里单选/复选显示的是**全部选项**，不是已选值 | 只能看列表行的「参与岗位」列判断，别被弹窗误导 |
| 9 | 弹窗残留 | 连续点两行的「查看」，第二次可能读到上一条的数据。**每读一条要重载页面** |
| 10 | 结算 T+1 | 今天的单明天 8 点才进明细，当天对不出数是正常的 |
| 11 | 结算记录有 8 列被隐藏 | 需要明细（规则、销售额、销量）时，这些列在 DOM 里，可以抓 |
| 12 | 「作废」未验证 | 没实测过点下去有没有二次确认，**动手前先在测试店试** |
| 13 | 「提成规则」这段文字后面拼了一整段**示例阶梯**（100/10%、200/15%、300/20%） | 用脚本解析真实阶梯时必须先按「提成规则示例」切掉，否则每条规则都会被多读出 3 档假数据，估算全错 |
| 14 | 会员拉新**只有固定提成** | 想按充值额比例奖励拉新，产品不支持，只能给人头费 |

## 十二、配置 SOP（从 0 配一套激励）

1. **先定口径**（找老板确认，写成一句话）：
   - 激励什么？商品推销 / 会员拉新 / 会员充值 / 旺云团购
   - 给谁？哪些岗位
   - 按件、按比例、还是按阶梯？比例是「分段」还是「整笔跳档」？
   - 多久算一次？每日 / 自然月 / 整段有效期
2. **算一遍成本**：拿历史日销/充值数据代入，算出每天、每月要发多少。**超过毛利就别配。**
3. 当前规则 → 新增 → 字段按 §五 填，注意字段会随场景/方式变化。
4. 保存后回列表核对「参与岗位」「参与商品」列显示是否正确。
5. 第二天早上 8 点后看「提成结算 → 未结算提成」有没有涨，验证规则真的在跑。
6. 月底确认结算设置：自动结算开关是否要开、结算方式（现金/微信/支付宝/银行卡）。

**排查「配了但没提成」的顺序**：规则生效时间是否已到 → 结束时间是否已过 → 参与岗位里的人是否真的在岗 → 商品范围是否覆盖卖的东西 → 计算周期是否到了结算点 → 未结算提成是否 T+1 才有数。

## 十三、脚本

`scripts/audit-commission.js`：只读审计。把当前 + 历史规则全部读出来，展开每条规则的阶梯值，
并按可配置的假设销售额估算日/月提成成本，用来发现「50% 这种明显配错」的规则。

改顶部 `ASSUME` 即可调整估算假设。
