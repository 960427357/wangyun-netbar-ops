# 旺云商户端 · 营销配置技能手册 v1（会员促销 + 活动管理）

> 路由前缀 `/memberActivityManage`、`/netBarActivity`，门店「演示门店」。
> 状态：2026-10-29 实测，弹窗字段为实际打开「新增」抓取，未提交任何数据。
> 用途：拉新、唤回、券、充值赠送、抽奖、签到、礼包。

---

## 一、结论先行

1. 营销分两大块：**会员促销**（按人群圈人、发券、充值赠送）和**活动管理**（抽奖、签到、游戏、礼包、商品促销）。
2. 促销的核心是「**先定人群，再配策略**」。人群是名单，策略是给这群人什么价。名单为空时策略不会触发，这是「配了没效果」的第一原因。
3. 券和礼包最容易踩的坑是**有效期**：券有「天数 / 固定日期」两种，礼包有「有效期」字段，选错就成永久券。
4. 商品促销的折扣作用在商超商品上，和区域计费无关，别混为一谈。

## 二、会员促销页面清单

| 页面 | 路由 | 作用 |
|---|---|---|
| 促销汇总 | `/memberActivityManage/summary` | 总览看板 |
| 促销人群 | `/memberActivityManage/promotion/*` | 8 类人群名单 |
| 促销历史 | `/memberActivityManage/history/*` | 进行中 / 待生效 / 已结束 |
| 策略设置 | `/memberActivityManage/strategy/*` | 每类人群的当前/历史策略 |
| 基础设置-规则设置 | `/memberActivityManage/baseConfig/rules` | 人群判定规则 |
| 基础设置-宣传文案 | `/memberActivityManage/baseConfig/advertising` | 客户端展示文案 |
| 充值赠送活动 | `/memberActivityManage/rechargeGift` | 充 X 送礼 |
| 商品优惠券 | `/memberActivityManage/coupon` | 券 + 赠送规则 |

### 2.1 八类人群（促销人群）

| 人群 | 路由片段 | 判定口径（据页面字段） |
|---|---|---|
| 流失预警 | `churnWarning` | 长期未上机 |
| 高净值人群 | `highNetWorth` | 累计消费高 |
| 线上人群 | `onlineCrowd` | 线上渠道来源 |
| 上机超时长人群 | `onlineOverTime` | 单次时长超阈值 |
| 会员生日 | `memberBirthday` | 按生日日期 |
| 促销日 | `memberDay` | 指定促销日 |
| 老带新 | `invitation` | 邀请关系 |
| 不参加人群 | `notParticipate` | 排除名单，优先级最高 |

「不参加人群」是黑名单式排除：配了促销策略后，名单里的人一律不参与，包括生日礼。

### 2.2 规则设置 `/memberActivityManage/baseConfig/rules`

一组开关 + 周期选择，标题即人群名：**高危人群 / 风险人群 / 休眠人群 / 线上人群 / 高净值人群 / 上机超长人群**，下方是 **周一~周日** 的复选。

页面底部「保 存」生效。这里决定每个「人群」在哪些星期被判为活跃，改完直接影响策略触达范围。

### 2.3 策略设置 `/memberActivityManage/strategy/*`

7 类人群各有一组「当前策略 / 历史策略」：
`riskGroup` 风险人群、`highRisk` 高危人群、`highNetWroth` 高净值人群、`onlineCrowd` 线上人群、`computerLongTime` 上机超时长人群、`salesDay` 促销日、`memberBirthday` 会员生日、`invitation` 老带新。

策略列表同构：当前策略可改，历史策略只读留痕。改策略等于改「这群人下次来享受什么」。

### 2.4 宣传文案 `/memberActivityManage/baseConfig/advertising`

列：# / 内容。按钮：新 增 / 编 辑 / 删 除。
纯文案库，客户端展示用。文案写「充值送 50」这种具体数字时，务必和充值赠送活动实际配置一致。

### 2.5 充值赠送活动 `/memberActivityManage/rechargeGift`

列表列：活动名称 / 有效期 / 礼品内容 / 状态 / 创建时间。筛选：活动名称、状态。按钮：搜 索 / 清 空 / 添 加 / 查看。

与 `/msBarOptions/deposit`（充值活动方案，只读，列 充值金额/赠送金额/允许修改金额/描述）**不是一回事**：

- `deposit` = 计费侧的固定充值档位，收银台直接用。
- `rechargeGift` = 营销侧的限时活动，可带礼品、有有效期。

两处都有赠送时，先确认是否叠加，避免充 100 送 30 + 活动再送 30。

### 2.6 商品优惠券 `/memberActivityManage/coupon`

两 tab：优惠券 / 赠送规则。

优惠券列表列：优惠券名称 / 一次消费金额 / 可抵扣金额 / 适用场景 / 适用用户 / 有效期（天|固定日期）。

新增弹窗「新 增」字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 优惠券名称 | 是 | 请输入 优惠券名称 |
| 一次消费金额 | 是 | 触发门槛 |
| 可抵扣金额 | 是 | 抵扣面额 |
| 适用场景 | 否 | 下拉，决定在哪类消费可用 |
| 适用用户 | 否 | 下拉，人群/等级 |
| 有效期 | 是 | 请输入 有效期天数 |

**有效期只有天数输入，没有日期选择**，要固定到期日就反推天数填。券一旦发出不可撤回，测试时先发 1 张。

## 三、活动管理页面清单

| 页面 | 路由 | 作用 |
|---|---|---|
| 整点抽奖 | `/netBarActivity/hoursActivity` | 到点开奖 |
| 积分-等级设置 | `/netBarActivity/scoreActivity/scoreSetting/grade` | 积分等级与参与限制 |
| 积分-签到赠送 | `/netBarActivity/scoreActivity/signIn/config` | 每日签到 |
| 积分-转盘抽奖 | `/netBarActivity/scoreActivity/lottery` | 消耗积分抽奖 |
| 积分-积分记录 | `/netBarActivity/scoreActivity/exchangeLog` | 流水 |
| 游戏活动 | `/netBarActivity/gameActivity/*` | LOL / 绝地求生 战绩活动 |
| 商品促销 | `/netBarActivity/promote` | 商超商品打折 |
| 礼包设置 | `/netBarActivity/giftPackage` | 礼包内容与成本 |

### 3.1 整点抽奖 `/netBarActivity/hoursActivity`

列：# / 活动名称 / 活动类型 / 活动时间 / 状态 / 创建时间。按钮：搜 索 / 清 空 / 添 加 / 查看 / 编 辑 / 删 除。
「添加」是跳转到独立配置页，不是弹窗——所以脚本抓弹窗会抓空，这是正常现象，别当成 bug。

### 3.2 积分活动

**等级设置** `scoreSetting/grade`：两 tab（等级设置 / 会员参与限制），列 等级名称 / 等级 / 所需积分 / 创建时间。
这是**积分等级**，不是计费会员等级，两套体系分开算，名字容易混。

**签到赠送** `signIn/config`：两 tab（签到活动设置 / 奖励发放记录）。字段「每日签到赠送」，列 有效期 / 礼品内容 / 活动状态 / 创建时间。按钮 保存 / 新增。

**转盘抽奖** `scoreActivity/lottery`：列 # / 活动名称 / 活动类型 / 活动时间 / 参与人限制 / 参与次数上限 / 每次消耗积分 / 状态 / 创建时间。
四个限制项要一起看：参与人 + 次数上限 + 每次积分 + 活动时间，任一项为 0 都可能抽不了。

### 3.3 游戏活动 `/netBarActivity/gameActivity/*`

总览 `overview`：tabs 全部 / LOL / 绝地求生。列 姓名 / 证件号 / 奖品明细 / 发放时间 / 状态 / 领取时间 / 游戏 / 活动名称 / 活动类型 / 战绩。
筛选：姓名、证件号、状态、游戏、活动名称。
子页 `pubg`、`lol` 是各游戏单独配置，`strategy/list` 是活动策略。

### 3.4 商品促销 `/netBarActivity/promote`

列：# / 活动名称 / 活动类型 / 商品类型 / 折扣 / 活动时间 / 是否过期 / 状态 / 创建时间。按钮：搜 索 / 清 空 / 添 加。
作用在商超商品，与上网费无关。「是否过期」由活动时间自动算，改时间即可复活。

### 3.5 礼包设置 `/netBarActivity/giftPackage`

列：礼包名称 / 礼包内容 / 预估成本 / 创建时间。

新增弹窗「新 增」字段：

| 字段 | 说明 |
|---|---|
| 礼包名称 | 请输入 礼包名称 |
| 礼包内容 | 请输入，多选商品 |
| 预估成本 | 请输入 预估成本 |

**预估成本是手填的**，不会自动按商品进货价算。做成本核算时要自己核一遍。

## 四、典型配置流程

### 场景 A：唤回流失会员

1. 规则设置里确认「休眠人群」的判定星期
2. 促销人群 → 流失预警，看名单是否非空
3. 策略设置 → 对应人群 → 新增当前策略（给折扣或券）
4. 商品优惠券 → 新增券（门槛 + 抵扣 + 天数）
5. 促销历史 → 进行中，确认已生效

### 场景 B：充值拉新

1. 计费设置 → 充值活动方案（只读，确认基础档位）
2. 会员促销 → 充值赠送活动 → 添加（限时 + 礼品）
3. 网吧配置 → 充值策略，确认「网民自助购买」开关
4. 会员等级 → 确认充值积分倍率是否也一起给

### 场景 C：日常活跃

1. 活动管理 → 积分活动 → 签到活动设置，配每日签到赠送
2. 转盘抽奖 → 配置消耗积分与次数上限
3. 礼包设置 → 配一个低成本礼包做签到大奖

## 五、红线

- 券/礼包**发出即不可撤回**，测试只用 1 个账号 1 张。
- 「不参加人群」会覆盖一切策略，配之前先看名单里有没有正常会员。
- 充值赠送与充值活动方案**可能叠加**，配第二个前先算总赠送率，超过 30% 要报老板。
- 商品促销改折扣后，检查商品原价是否被改成促销价（促销应打折，不是改原价）。

## 六、校验清单

| 检查项 | 期望 |
|---|---|
| 人群名单是否非空 | 空名单 = 策略不触发 |
| 策略是否在有效期内 | 过期策略在「已结束」里 |
| 券有效期天数是否合理 | 误填 3650 等于永久 |
| 转盘四项限制是否齐全 | 缺一项抽不了 |
| 礼包成本是否手填正确 | 系统不自动算 |
| 积分等级与计费等级是否混淆 | 两套体系，别互相套 |
