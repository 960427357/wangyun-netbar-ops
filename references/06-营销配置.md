# 旺云商户端 · 营销配置技能手册 v1（会员促销 + 活动管理）

> 路由前缀 `/memberActivityManage`、`/netBarActivity`，门店「演示门店」。
> 状态：2026-10-29 实测，弹窗字段为实际打开「新增」抓取，未提交任何数据。
> 用途：拉新、唤回、券、充值赠送、抽奖、签到、礼包。

---

## 一、结论先行

1. 营销分两大块：**会员促销**（按人群圈人、发券、充值赠送）和**活动管理**（抽奖、签到、游戏、礼包、商品促销）。
2. 促销的核心是「**先定人群，再配策略**」。人群是名单，策略是给这群人什么价。名单为空时策略不会触发，这是「配了没效果」的第一原因。
3. 券和礼包最容易踩的坑是**有效期**：券有「天数 / 固定日期」两种，礼包有「有效期」字段，选错就成永久券。
4. 商品促销的折扣作用在商超商品上，和区域计费无关，别混为一谈。

### 2.1 八类人群（促销人群）

| 人群 | 路由片段 | 判定口径（据页面字段） |
|---|---|---|
| 流失预警 | `churnWarning` | 长期未上机 |
| 高净值人群 | `highNetWorth` | 累计消费高 |
| 线上人群 | `onlineCrowd` | 线上渠道来源 |
| 上机超时长人群 | `onlineOverTime` | 单次时长超阈值 |
| 会员生日 | `memberBirthday` | 按生日日期 |
| 促销日 | `memberDay` | 指定促销日 |
| 老带新 | `invitation` | 邀请关系 |
| 不参加人群 | `notParticipate` | 排除名单，优先级最高 |

「不参加人群」是黑名单式排除：配了促销策略后，名单里的人一律不参与，包括生日礼。

### 2.2 规则设置 `/memberActivityManage/baseConfig/rules`

一组开关 + 周期选择，标题即人群名：**高危人群 / 风险人群 / 休眠人群 / 线上人群 / 高净值人群 / 上机超长人群**，下方是 **周一~周日** 的复选。

页面底部「保 存」生效。这里决定每个「人群」在哪些星期被判为活跃，改完直接影响策略触达范围。

### 2.3 策略设置 `/memberActivityManage/strategy/*`

7 类人群各有一组「当前策略 / 历史策略」：
`riskGroup` 风险人群、`highRisk` 高危人群、`highNetWroth` 高净值人群、`onlineCrowd` 线上人群、`computerLongTime` 上机超时长人群、`salesDay` 促销日、`memberBirthday` 会员生日、`invitation` 老带新。

策略列表同构：当前策略可改，历史策略只读留痕。改策略等于改「这群人下次来享受什么」。

### 2.4 宣传文案 `/memberActivityManage/baseConfig/advertising`

列：# / 内容。按钮：新 增 / 编 辑 / 删 除。
纯文案库，客户端展示用。文案写「充值送 50」这种具体数字时，务必和充值赠送活动实际配置一致。

### 2.5 充值赠送活动 `/memberActivityManage/rechargeGift`

列表列：活动名称 / 有效期 / 礼品内容 / 状态 / 创建时间 / 操作。筛选：活动名称、状态。按钮：搜 索 / 清 空 / 添 加。
列表可以有多条并存，每条各自有独立的状态开关。

与 `/msBarOptions/deposit`（充值活动方案，只读，列 充值金额/赠送金额/允许修改金额/描述）**不是一回事**：

- `deposit` = 计费侧的固定充值档位，收银台直接用。
- `rechargeGift` = 营销侧的限时活动，可带礼品、有有效期。

两处都有赠送时，先确认是否叠加，避免充 100 送 30 + 活动再送 30。
再叠加 `09-门店资料` §3.2 的「充值策略」（充X送Y 元），一共三处会给钱，配第二个之前先算总赠送率。

#### ★ 状态开关 + 操作按钮的隐藏规则（2026-10-31 实测）

「状态」列是 **`el-switch` 开关**，点一下立刻切换、**无二次确认**，成功 toast「操作成功」。

**活动启用（开关 on）时，操作列只有「查看」；把开关关掉、活动停用之后，「编辑 / 删除」才出现。**
所以「想改某条活动」的正确路径是：**先停用 → 操作列变成「查看 编辑 删除」→ 再编辑**。
别看到只有「查看」就以为这页不支持修改（旧版本这里就是这么误记的）。

#### 「添 加」是跳独立页，不是弹窗

`/netBar/addMemberActivity?actType=recharge`；查看详情是同一页带 `&id=<活动id>&openType=view`（只读）。
**保存成功后自动跳回列表页**，不弹 toast，判断成败只能回列表看新增的那条。

表单字段（按页面顺序）：

| 字段 | 控件 | 说明 |
|---|---|---|
| 活动名称 | 文本，最长 50 | |
| 有效期 | 单选：**长久有效（默认） / 时间范围** | 选「时间范围」后要填起止 |
| 开启活动 | 开关，**默认关** | 不打开则不生效 |
| 奖品内容 | 见下，最多 6 档 | |

#### 奖品档位：「充值满 X 元，赠送抽奖 N 次」

每档是 `.prizeItemBorder`，文案固定为「充值满 `[cash]` 元 ，赠送抽奖 `[n]` 次」，
块内就是两个 `input[type=number]`：**第 1 个 = 充值门槛（元），第 2 个 = 赠送抽奖次数**。

一档除了抽奖次数，还能同时挂：
- **赠送专场卡**（「选择专场卡」按钮）
- **商品**（「选择商品」，最多 9 个）

按钮：「添加规则」增加一档（**最多 6 档**，超出按钮失效）；「移动」拖动排序；
**单档时块内没有「删除」按钮，加到 2 档后每块才出现「删除」**。

> ⚠️ **这是档位制，不是累进制。**
> 「充值满 X 元」是一组并列的门槛，不是「每满 X 元自动加一次」。
> 想表达「每满 50 送 1 次」，只能用多档去逼近（50/100/150/200/250/300 → 1/2/3/4/5/6），
> 代价是 **6 档上限、300 元以上封顶 6 次**。
> 多档之间到底是「命中最高的那一档、只发一份奖品包」还是「逐档累加」，**没有实测过**
> （要验证得真实充值，测试环境做不到）。**跟客户讲的时候必须说清这一点，不能拍胸脯保证累加。**

#### 接口明文，可以直接核对数据

查看详情时 `GET /business-wy/activitiesInfo/detail` 返回 **明文 JSON**（不像别的接口加密），
用来复核配置最可靠：

```
activityName / type=9（充值赠送）/ status=1 开启 / openStartTime 00:00:00 openEndTime 23:59:59
prizeList[]  ← 一档一条
  ├ cash          = 充值门槛（元）
  ├ name          = "充值满50元"（系统自动拼）
  └ prizeRelationList[]
      ├ prizeType = 4        ← 4 就是「赠送抽奖 N 次」
      ├ prizeNum  = N        ← 送几次
      └ prizeName = "赠送抽奖1次"
```

脚本：`scripts/create-recharge-gift.js`（`SAVE=false` 只填不存）。改 `CFG.name` 与 `CFG.rules` 数组即可复用，
`rules` 里一条就是一个档位 `{cash, lottery}`。

### 2.6 商品优惠券 `/memberActivityManage/coupon`

两 tab：优惠券 / 赠送规则。

优惠券列表列：优惠券名称 / 一次消费金额 / 可抵扣金额 / 适用场景 / 适用用户 / 有效期（天|固定日期）。

新增弹窗「新 增」字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 优惠券名称 | 是 | 请输入 优惠券名称 |
| 一次消费金额 | 是 | 触发门槛 |
| 可抵扣金额 | 是 | 抵扣面额 |
| 适用场景 | 否 | 下拉，决定在哪类消费可用 |
| 适用用户 | 否 | 下拉，人群/等级 |
| 有效期 | 是 | 请输入 有效期天数 |

**有效期只有天数输入，没有日期选择**，要固定到期日就反推天数填。券一旦发出不可撤回，测试时先发 1 张。

### 3.2 积分活动

**等级设置** `scoreSetting/grade`：两 tab（等级设置 / 会员参与限制），列 等级名称 / 等级 / 所需积分 / 创建时间。
这是**积分等级**，不是计费会员等级，两套体系分开算，名字容易混。

**签到赠送** `signIn/config`：两 tab（签到活动设置 / 奖励发放记录）。左子导航四项
（积分设置 / 签到赠送 / 转盘抽奖 / 积分记录）。上半是「每日签到赠送 [N] 积分 + 保存」，
下半是「活动列表」（有效期 / 礼品内容 / 活动状态 / 创建时间 / 操作）。
**这一页是三层结构、字段多、坑也多，完整版见 `14-积分签到.md`**，不要只看这一句就动手。

**转盘抽奖** `scoreActivity/lottery`

列：# / 活动名称 / 活动类型 / 活动时间 / 参与人限制 / 参与次数上限 / 每次消耗积分 / 状态 / 创建时间 / 操作。
列表操作**只有「查看 / 删除」，没有「编辑」**——活动一旦建成不能改，要改只能删了重建。

> ⚠️ 旧版本这里写过「次数上限等任一项为 0 都可能抽不了」，**这是错的**。次数上限填 0 不是抽不了，
> 而是**主动关闭积分抽奖**（见下）。别照着旧结论去劝客户把 0 改大。

**「添 加」不是弹窗，是新开一个独立配置页** `/netBar/addActivity?actType=lottery`。
提交成功后**这个标签页会自己关掉**（URL 变成 `about:blank`），所以脚本抓不到 toast，
判断成败只能回列表页看有没有新增那条。别把「抓不到提示」当成失败。

**表单字段（按页面顺序）**

| 字段 | 控件 | 说明 |
|---|---|---|
| 活动名称 | 文本，最长 50 | |
| 活动类型 | 下拉，**只有「幸运转盘」一项** | 无别的类型可选 |
| 参与人限制 | 复选：不限制 / 临时卡 / 会员等级限制 | 默认「不限制」 |
| 活动开放规则 | 下拉：每日 / 每周 / 每月 / 指定日期 | |
| 活动日期 | 随开放规则变 | 选「每日」时显示「每天开放」 |
| 活动开放时间 / 结束时间 | 时间，默认 00:00 / 23:59 | 这是每天的时段，不是活动起止日期 |
| 参与抽奖设置 | 见下 | |
| 排序 | 数字 | 可空 |
| 开启活动 | 开关，**默认关** | 不打开则活动不生效 |
| 活动奖项 | 见下 | 最多 6 个 |

**★ 参与抽奖设置：次数上限填 0 = 关掉积分抽奖**

区块标题固定写「积分抽奖规则」，内含：

- 每人 + 「每个自然日 / 每周 / 每月」下拉（默认**灰掉不可选**，值随「活动开放规则」走）
- **积分参与次数上限**（人/周期内最多用积分抽几次）
- **积分抽奖每次消耗**（每次扣多少积分）

把「积分参与次数上限」填 **0** 之后，页面会**自动出现一句系统提示**：

> **不发放积分抽奖，顾客仍可参与赠送抽奖。**

同时「积分抽奖每次消耗」会被**清空并禁用**。这就是「只能用赠送的抽奖次数抽、不能花积分抽」的实现方式，
产品没有独立的「抽奖次数」开关，靠这个 0 来表达。（2026-10-31 实测，建出的活动列表显示 次数上限 0 / 每次消耗 0）

**活动奖项区**：每个奖项是 `.prizeItemBorder`，按钮「追加奖项」增加，最多 6 个，可拖动排序。

- 奖项名称（50 字）、奖项数量、中奖概率（**百分数，填 10 就是 10%**）
- 奖品内容：**按钮式单选「奖品 / 谢谢参与」**（`.el-radio-button`，不是 `.el-radio`）
- 选「奖品」时下方出现四选一：礼品套餐（选择）/ 专场卡（选择专场卡）/ **赠送网费（数字框，元）** / 商品（选择商品，最多 9 个）
- 选「谢谢参与」时**「奖项数量」和整个奖品内容区自动隐藏**——谢谢参与不占库存，不用填。

**保存后的状态**：列表「状态」列可能为空，但进「查看」详情页（`&openType=view`，只读）
看「开启活动」开关是 `true` 即为已开启。判断是否生效以详情页开关为准，不要只看列表状态列。

## 四、典型配置流程

### 场景 A：唤回流失会员

1. 规则设置里确认「休眠人群」的判定星期
2. 促销人群 → 流失预警，看名单是否非空
3. 策略设置 → 对应人群 → 新增当前策略（给折扣或券）
4. 商品优惠券 → 新增券（门槛 + 抵扣 + 天数）
5. 促销历史 → 进行中，确认已生效

### 场景 B：充值拉新

1. 计费设置 → 充值活动方案（只读，确认基础档位）
2. 会员促销 → 充值赠送活动 → 添加（限时 + 礼品）：档位填「充值满 X 元，赠送抽奖 N 次」，
   一档还能同时挂专场卡和商品；最多 6 档。**配之前先看列表里有没有旧的占位活动还开着**
   （例如「充值满 0.01 元送抽奖 1 次」），旧的没关会把新规则完全冲掉。
3. 网吧配置 → 充值策略，确认「网民自助购买」开关
4. 会员等级 → 确认充值积分倍率是否也一起给

### 场景 C：日常活跃

1. 活动管理 → 积分活动 → 签到活动设置，配每日签到赠送
2. 转盘抽奖 → 配置消耗积分与次数上限
3. 礼包设置 → 配一个低成本礼包做签到大奖

## 五、红线

- 券/礼包**发出即不可撤回**，测试只用 1 个账号 1 张。
- 「不参加人群」会覆盖一切策略，配之前先看名单里有没有正常会员。
- 充值赠送与充值活动方案**可能叠加**，配第二个前先算总赠送率，超过 30% 要报老板。
- 商品促销改折扣后，检查商品原价是否被改成促销价（促销应打折，不是改原价）。

## 六、校验清单

| 检查项 | 期望 |
|---|---|
| 人群名单是否非空 | 空名单 = 策略不触发 |
| 策略是否在有效期内 | 过期策略在「已结束」里 |
| 券有效期天数是否合理 | 误填 3650 等于永久 |
| 转盘四项限制是否齐全 | 缺一项抽不了 |
| 礼包成本是否手填正确 | 系统不自动算 |
| 积分等级与计费等级是否混淆 | 两套体系，别互相套 |
